# @boobooking/dashboard-ui-components

Компоненты дашборда на Vue 3: фильтры и общие элементы интерфейса.

## Установка

    npm install @boobooking/dashboard-ui-components

```js
import { RussianMobileFilter, SelectDateInterval } from '@boobooking/dashboard-ui-components'
import '@boobooking/dashboard-ui-components/style.css'
```

Стили пакета подключаются **до** стилей приложения.

## Требования

Vue не ниже 3.5, ESM, сборщик, умеющий импорт CSS из пакета. Версия 3.5 нужна
ради `useId()`: им компоненты связывают свои `id` с `aria-`атрибутами, и две
копии компонента на одной странице не делят один `id`.

Tailwind, `@tailwindcss/forms`, Inertia и какие-либо токены в CSS приложения
пакету не нужны.

## Компоненты

Пакет экспортирует четырнадцать компонентов: `Popup`, `Dot`, `PickDay`,
`RussianMobileFilter`, `Search`, `SelectDateInterval`, `SelectSingle`,
`SmallBadge`, `ErrorMessages`, `Closer`, `DownloadLink`, `Modal`,
`ConfirmationModal`, `DropdownButtonWithAction`. В архив пакета
(`files: ["dist"]`) исходники не
попадают, поэтому контракт каждого компонента — здесь и в playground, а не в
исходном коде.

### Popup

Всплывающее меню с оверлеем, закрывающим по клику вне, и переходом на
открытие/закрытие. Другие компоненты пакета используют его как обёртку над
своим содержимым — некоторые напрямую, некоторые через внутренние
компоненты.

    <popup v-model="isOpen" align="right">
        …содержимое меню…
    </popup>

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `Boolean` | `false` | Открыто ли меню |
| `align` | `String` | `"left"` | `"left"` или `"right"` — с какой стороны прижать меню |

Событие: `update:modelValue` — при каждом открытии и закрытии, включая клик по
оверлею.

У `Popup` нет события `changed`, и это не пропуск — см. раздел
«Почему у Popup и Dot нет события changed».

### Dot

Индикатор-точка: красная или зелёная, с пульсацией или без.

    <dot color="green" :with-pulse="isLive" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `color` | `String` | обязателен | `"red"` или `"green"` |
| `withPulse` | `Boolean` | `false` | Добавляет анимацию пульсации |

Событий нет. Значения у `Dot` тоже нет — см. раздел
«Почему у Popup и Dot нет события changed».

### PickDay

Поле выбора одной даты на Pikaday, с ластиком очистки.

    <pick-day v-model="date" placeholder-text="от" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `String` | `""` | Текущая дата |
| `withEraser` | `Boolean` | `true` | Показывать ли ластик очистки |
| `placeholderText` | `String` | `""` | Текст подсказки в пустом поле |

События: `update:modelValue` — при выборе даты в календаре и при очистке
(пустой строкой); `changed` — в тех же двух случаях, для использования наравне
с остальными фильтрами.

### RussianMobileFilter

Поле ввода российского мобильного номера с маской `+7 (000) 000 00 00` и
дебаунсом перед отправкой.

    <russian-mobile-filter v-model="phone" header="Телефон" @changed="reload" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `String` | `""` | Номер: цифры вместе с кодом страны, без «+» (например, `79031234567`), либо пустая строка |
| `header` | `String` | обязателен | Подпись поля |
| `isRequired` | `Boolean` | `false` | Пометка обязательности в заголовке |
| `isLoading` | `Boolean` | `false` | Индикатор загрузки в заголовке |

«+» — неудачный символ для URL, поэтому в параметре только цифры; плюс к
номеру дописывает бэкенд.

События: `update:modelValue` — на каждое принятое маской изменение;
`changed` — через 400 мс паузы после ввода, начиная с третьей цифры (раньше
событие не летит вовсе), а также сразу — без дебаунса — при опустевшем поле,
по клику на ластик, по Enter и по уходу фокуса. Дублей не бывает: компонент
помнит последнее отправленное значение и не шлёт его повторно.

### Search

Текстовое поле поиска с ластиком очистки.

    <search v-model="query" header="Поиск" @changed="reload" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `String` | `""` | Текущий текст поиска |
| `header` | `String` | обязателен | Подпись поля |
| `isRequired` | `Boolean` | `false` | Пометка обязательности в заголовке |
| `isLoading` | `Boolean` | `false` | Индикатор загрузки в заголовке |

События: `update:modelValue` и `changed` — оба на каждый ввод. Значение,
изменённое родителем, поле показывает сразу и без событий: ответный
`update:modelValue` вернул бы родителю его же значение.

### SelectDateInterval

Пара `PickDay` под одним заголовком — интервал дат «от» и «до».

    <select-date-interval
        header="Период"
        :date-from="dateFrom"
        :date-to="dateTo"
        @update:date-from="dateFrom = $event"
        @update:date-to="dateTo = $event"
        @changed="reload"
    />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `dateFrom` | `String` | `""` | Начало интервала |
| `dateTo` | `String` | `""` | Конец интервала |
| `header` | `String` | обязателен | Подпись поля |
| `isRequired` | `Boolean` | `false` | Пометка обязательности в заголовке |
| `isLoading` | `Boolean` | `false` | Индикатор загрузки в заголовке |

События: `update:dateFrom`, `update:dateTo` — на каждый выбор в
соответствующем `PickDay`; `changed` — когда новое значение отличается от
переданного пропса (отдельно для каждой из двух дат).

### SelectSingle

    <select-single
        header="Вендор"
        :items="[{ id: 'a', name: 'Первый' }]"
        v-model="vendor"
        @changed="reload"
    />

`items` — массив объектов `{ id, name }`. `v-model` держит `id` выбранного или
`null`, если не выбрано.

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `items` | `Array` | обязателен | Массив `{ id, name }` |
| `modelValue` | `String \| Number` | `null` | `id` выбранного элемента или `null` |
| `header` | `String` | обязателен | Подпись поля |
| `isRequired` | `Boolean` | `false` | Пометка обязательности в заголовке |
| `isLoading` | `Boolean` | `false` | Индикатор загрузки в заголовке |

События: `update:modelValue` и `changed` — при выборе элемента (повторный
клик по уже выбранному снимает выбор) и при очистке через ластик.

### SmallBadge

Бейдж-пилюля с коротким текстом. Текст не переносится.

    <small-badge text="Отправлено" color="green" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `text` | `String` | обязателен | Текст бейджа |
| `color` | `String` | обязателен | `"green"`, `"indigo"`, `"gray"`, `"blue"`, `"red"` или `"yellow"` |

Событий нет.

### ErrorMessages

Плашка со списком сообщений: жёлтая для предупреждений, красная для ошибок.
Без сообщений не отрисовывается вовсе.

    <error-messages :messages="errors" type="dangerous" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `messages` | `Object \| Array` | обязателен | Объект ошибок валидации (ключ — поле, значение — текст) или массив строк |
| `type` | `String` | `"warning"` | `"warning"` (жёлтая) или `"dangerous"` (красная) |

Событий нет.

### Closer

Кнопка-крестик закрытия. Размер и положение задаёт приложение классами на
корне: без классов размера крестик получает размер SVG по умолчанию
(300×300).

    <closer class="absolute top-0 right-0 w-8 h-8" @clicked="close" />

Пропов нет. Событие: `clicked` — по клику.

### DownloadLink

Ссылка на файл в виде бейджа с иконкой скачивания. Кликабелен весь бейдж.

    <download-link :url="exportUrl" title="скачать xlsx" />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `url` | `String` | обязателен | Адрес файла |
| `title` | `String` | `"Скачать"` | Подпись и всплывающая подсказка |

Событий нет.

### Modal

Оболочка модального окна: оверлей, панель и переходы открытия и закрытия.
Заголовок, текст и кнопки кладёт в слот приложение. На этой оболочке построен
`ConfirmationModal`.

    <modal :is-open="isOpen" :heading-id="headingId">
        <h3 :id="headingId">Заголовок</h3>
        …содержимое…
    </modal>

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `isOpen` | `Boolean` | `false` | Открыта ли модалка |
| `headingId` | `String` | обязателен | `id` заголовка в слоте: им модалка подписывает диалог через `aria-labelledby` |

Событий нет. Модалка не закрывается сама ни по клику на оверлей, ни по
Escape: видимостью управляет родитель, как у `ConfirmationModal`. `id`
заголовка удобно получать через `useId()` — тогда у двух модалок на одной
странице он не совпадёт.

Содержимое слота смонтировано всегда, а закрытая модалка его только прячет
(`v-show`). Поэтому состояние внутри — выбор, введённый текст, ошибки —
переживает закрытие, и сбрасывать его должен родитель.

Панель белая, со скруглением `rounded-lg` и без внутренних отступов: их
задаёт содержимое слота. На узком экране панель прижата к нижнему краю, а её
ширина — по содержимому, но не больше экрана за вычетом полей; начиная с `sm`
панель стоит по центру и занимает `max-w-lg`. `class` и другие атрибуты на
`<modal>` попадают на полноэкранный корень, а не на панель: размер панели и
атрибуты диалога вроде `aria-describedby` снаружи не задаются.

### ConfirmationModal

Модалка подтверждения действия: заголовок, текст, кнопка действия и кнопка
отмены.

    <confirmation-modal
        :is-open="showDelete"
        type="dangerous"
        confirmation-heading="Удаление администратора"
        confirmation-text="Это действие необратимо."
        action-button-text="Удалить"
        @action-canceled="showDelete = false"
        @action-confirmed="deleteUser"
    />

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `isOpen` | `Boolean` | `false` | Открыта ли модалка |
| `type` | `String` | `"warning"` | `"warning"` (жёлтая) или `"dangerous"` (красная) |
| `confirmationHeading` | `String` | `""` | Заголовок |
| `confirmationText` | `String` | `""` | Текст под заголовком |
| `cancelButtonText` | `String` | `"Отмена"` | Подпись кнопки отмены |
| `actionButtonText` | `String` | обязателен | Подпись кнопки действия |

События: `actionConfirmed` — по кнопке действия, `actionCanceled` — по кнопке
отмены. Ни одна из кнопок модалку не закрывает — см. раздел «Почему у
ConfirmationModal нет v-model».

### DropdownButtonWithAction

Кнопка с меню дополнительных действий: основная часть — слот `button`, стрелка
справа открывает меню из слота `actions`. Без слота `actions` стрелки нет, и
кнопка скругляется с обеих сторон.

    <dropdown-button-with-action v-model="menuIsOpen">
        <template #button>…основное действие…</template>
        <template #actions>…пункты меню…</template>
    </dropdown-button-with-action>

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `Boolean` | `false` | Открыто ли меню |

Событие: `update:modelValue` — только когда меню открыл или закрыл сам
компонент: клик по стрелке, клик вне меню, Escape. Значение, пришедшее от
родителя, компонент принимает молча: ответное событие вернуло бы родителю его
же решение. Без `v-model` меню работает само по себе.

## Правила API пакета

Компонент, добавляемый в пакет, следует тем же правилам, что и уже
имеющиеся:

- Значение компонента передаётся через `v-model` (проп `modelValue` и
  событие `update:modelValue`) и не обязательно: компонент обязан
  отрисовываться без переданного значения. `required: true` оставляют
  только там, без чего компонент бессмыслен, — например, у `items` в
  `SelectSingle` или у `header` во всех фильтрах.
- Именованные модели (`v-model:date-from`, `v-model:date-to`, как у
  `SelectDateInterval`) — исключение для компонентов с несколькими
  значениями. У компонента с одним значением именованная модель не нужна:
  для него это и есть обычный `v-model`.
- Булев проп называется `is*`, если описывает состояние компонента
  (`isRequired`, `isLoading`), и `with*`, если описывает необязательную
  возможность (`withEraser` у `PickDay`, `withPulse` у `Dot`).
- Проп-перечисление — ограниченный набор строковых значений, как `color` у
  `Dot` или `align` у `Popup`, — обязательно имеет `validator`,
  отклоняющий значения вне списка.

## Почему у Popup и Dot нет события changed

`changed` означает не «значение изменилось», а «пользователь закончил
выбор, можно обновлять выдачу» — фильтры дашборда эмитят его как сигнал к
перезапросу данных.

У `Popup` такого момента нет: он не хранит значение фильтра, а лишь
управляет видимостью меню, и открытие меню — не повод перезагружать
данные. Момент, когда выбор действительно завершён, отслеживает
компонент, который использует `Popup` — сам или через внутренние
компоненты пакета, — `changed` эмитит он.

У `Dot` события нет по другой причине: у него нет значения вообще, поэтому
эмитить не о чем.

Отсутствие `changed` у `Popup` и `Dot` — сознательное решение, а не
пропуск.

## Почему у ConfirmationModal нет v-model

Правило пакета — значение через `v-model` — относится к состоянию, которое
компонент меняет сам: `Popup` закрывается по клику вне, `SelectSingle` меняет
выбор. `ConfirmationModal` свою видимость не меняет никогда. Обе кнопки только
сообщают родителю решение пользователя, а закрыть модалку, оставить её открытой
на время запроса или открыть следующую — решает родитель.

`v-model` обещал бы двустороннюю связь, которой нет, поэтому видимость
передаётся пропом `isOpen`.

## Playground

    npm run playground

Поднимает демо-страницы со всеми четырнадцатью компонентами в двух окружениях:
голом (без Tailwind и стилей приложения) и в окружении приложения (с
Tailwind, `@tailwindcss/forms` и типографикой, как у потребителя). Это
основной способ посмотреть, как компоненты выглядят и ведут себя, а не
угадывать по исходникам или по этому README.

## Что пакет берёт у приложения

Базовую типографику — семейство шрифта, размер, `line-height`. Он наследует её
намеренно, чтобы не навязывать свой шрифт дашборду с собственным. В приложении,
которое типографику не задаёт, компоненты отрисуются браузерными умолчаниями:
рабочими, но чужими на вид.

Компоненты русскоязычные: названия месяцев, подписи и правила номера телефона
зашиты.

## Ограничение

Пакет отдаёт скомпилированные утилиты Tailwind — те же имена классов, что
генерирует Tailwind приложения. При стоковой палитре правила совпадают. Если
приложение переопределит стоковый цвет, одноимённые правила столкнутся и
победит подключённое позже, то есть компоненты возьмут палитру приложения.

Ресет пакета распространяется и на содержимое слотов — разметку приложения
внутри `Popup`, `DropdownButtonWithAction` и `Modal`. Ресет лежит в слое
`components`, поэтому внутри слота он сильнее всего, что приложение объявило
в слое `base`, — preflight и `@tailwindcss/forms`. Сам ресет повторяет
preflight, так что обычная разметка в приложении с preflight почти не
меняется, а без preflight получит `box-sizing` и снятые границы. Поля ввода
в слоте теряют оформление `@tailwindcss/forms`: рамку, фон, скругление и
кольцо фокуса. Вернуть его можно утилитами — слой `utilities` сильнее
ресета. Например, чекбоксу: `border border-gray-300 bg-white rounded-sm
checked:bg-current focus:ring-2 focus:ring-offset-2`.

У `Closer` нет доступного имени, и он выключен из порядка табуляции
(`tabindex="-1"`): скринридер его не назовёт, а с клавиатуры до него не
добраться.

`Modal` и построенный на нём `ConfirmationModal` не переносят фокус внутрь при
открытии, не удерживают его внутри, не возвращают на прежнее место после
закрытия и не закрываются по Escape.
