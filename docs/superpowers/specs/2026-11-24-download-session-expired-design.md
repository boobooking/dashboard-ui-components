# downloadFile: истёкшая сессия отдельно от остальных отказов

Дата: 2026-11-24

## 1. Цель и рамки

Когда сессия Laravel истекла, а вкладка дашборда так и осталась открытой,
скачивание отчёта не должно молча ломаться. Страница должна узнать, что дело
именно в сессии, и показать уведомление «сессия закончилась, обновите
страницу». Повод — дашборд vetkit: там при истёкшей сессии кнопка «Скачать»
сохраняла страницу входа как `export.htm`. vetkit переводится на пакет
отдельной задачей, а этот сценарий пакет должен закрывать сам.

В рамках задачи:

- `downloadFile` шлёт заголовок, после которого Laravel на истёкшую сессию
  отвечает `401`, а не перенаправлением;
- отказ на `401` помечается как истёкшая сессия;
- тесты и README.

Вне рамок:

- текст уведомления: его пишет страница, у пакета нет API для текстов
  (решение владельца, вариант A);
- изменения `NotificationMessage`;
- страницы cashback и certificates, а также перевод vetkit на пакет —
  отдельные задачи в репозиториях проектов, после выпуска;
- выпуск: версия, тег и публикация — по слову владельца.

## 2. Что показало исследование

- `src/download.js`: `fetch(url, { credentials: 'same-origin' })`, без
  заголовков. Отказ при `response.redirected` даёт поля
  `redirectUrl: response.url, status: null`, отказ при `!response.ok` —
  `redirectUrl: null, status`. Сетевая ошибка отклоняет promise ошибкой
  `fetch` без этих полей.
- Middleware `auth` у Laravel при `$request->expectsJson()` бросает
  `AuthenticationException`, которая рендерится в `401`, иначе отдаёт `302`
  на `route('login')`. `expectsJson()` — это `(ajax() && !pjax() &&
  acceptsAnyContentType()) || wantsJson()`. У `fetch` по умолчанию
  `Accept: */*`, поэтому заголовка `X-Requested-With: XMLHttpRequest`
  достаточно. Проверено на vetkit: без сессии
  `GET /dashboard/reports/export` отвечает `302 Location: …/dashboard/login`,
  `text/html`.
- `expectsJson()` Laravel использует не только в `auth`, но и при ошибке
  валидации: с заголовком невалидный запрос получает `422` JSON вместо `302`
  назад. Выгрузки cashback и certificates валидируют `phone`; проба Codex на
  Laravel 13.25.0 (`.project-context/sessions/2026-11-24-download-session-expired/laravel-probe.log`)
  показала `422` вместо `302` для невалидного `phone` в выгрузке certificates.
- Inertia шлёт `X-Requested-With: XMLHttpRequest` на каждый свой запрос, так
  что для бэкендов дашбордов этот заголовок не новый.
- Сейчас `downloadFile` вызывают cashback (`Pages/Cashbacks/Index.vue`) и
  certificates (`Pages/Groups/Index.vue`, `Pages/Groups/Card.vue`,
  `Pages/Orders/Index.vue`). На `error.redirectUrl` они уходят через
  `router.visit`, в остальных случаях пишут «Попробуйте ещё раз». После
  изменения пакета истёкшая сессия придёт к ним как `401`, и пока страницы не
  обновлены, они покажут «Попробуйте ещё раз» вместо перехода на вход.
- Тесты: `tests/download.test.js` подменяет `fetch` (happy-dom), а
  `tests/download.server.test.js` гоняет настоящий `fetch` Node против
  настоящего HTTP-сервера.

## 3. Подходы

| Подход | Чем плох / хорош | Итог |
| --- | --- | --- |
| Заголовок `X-Requested-With: XMLHttpRequest`, `401` → `sessionExpired` | Меняет ответы, которые Laravel строит по `expectsJson()`: гость получает `401` вместо `302` на вход, невалидный запрос — `422` вместо `302` назад. Тот же заголовок шлёт Inertia | выбран |
| Без заголовка, считать истёкшей сессией любое перенаправление | Пакет не знает адреса страницы входа: любое другое перенаправление примет за конец сессии | отброшен |
| `Accept: application/json` | Тоже даёт `401`, но переключает в JSON и другие ответы, например страницы ошибок. Для скачивания файла это лишнее | отброшен |

## 4. Решения и их источники

| Решение | Источник |
| --- | --- |
| Пакет выделяет `401` отдельно, страница показывает уведомление с предложением обновить страницу | владелец |
| Текст уведомления пишет страница, пакет только помечает отказ (вариант A) | владелец |
| Сигнал — заголовок `X-Requested-With: XMLHttpRequest` | автор, согласовано с владельцем |
| Поле отказа — `sessionExpired` (булево), у `401` `true` | автор |
| `sessionExpired: false` у отказов на перенаправление и прочие коды, чтобы у отказов с причиной был один набор полей | автор |
| Ветка `redirectUrl` остаётся: перенаправление по другим причинам возможно | автор |
| Истёкшей сессией считается только `401`. `403` (нет прав) и `419` (CSRF, на `GET` не бывает) — обычные отказы с кодом | автор |
| Версия минорная (0.26.0): страницы, которые полагаются на `redirectUrl` при истёкшей сессии, меняют поведение | автор |
| Playground не меняется: его статический сервер не умеет отвечать `401` | автор |
| Работа идёт в `main`, как и вся история пакета | автор |

## 5. Поведение

Запрос: `fetch(url, { credentials: 'same-origin', headers: { 'X-Requested-With': 'XMLHttpRequest' } })`.

| Ответ | Результат |
| --- | --- |
| перенаправление (`response.redirected`) | отказ: `redirectUrl` — `response.url`, `status` — `null`, `sessionExpired` — `false`; сообщение прежнее |
| `401` без перенаправления | отказ: `status` — `401`, `redirectUrl` — `null`, `sessionExpired` — `true`; сообщение — `downloadFile: сессия истекла, ответ 401 на ${url}` |
| другой не `2xx` | отказ: `status` — код, `redirectUrl` — `null`, `sessionExpired` — `false`; сообщение прежнее |
| `2xx` | файл, как сейчас |
| сетевая ошибка | отказ ошибкой `fetch`, без полей причины, как сейчас |

Порядок проверок прежний: сначала перенаправление, затем `!ok`.

«Как раньше» относится к обработке уже полученного HTTP-ответа. Сам ответ
сервера из-за заголовка может стать другим: на невалидные параметры выгрузки
Laravel вместо `302` назад отвечает `422`, и это обычный отказ со
`status: 422`, `sessionExpired: false`. Страница, которая на такой отказ
переходила по `redirectUrl`, теперь попадёт в общую ветку («Попробуйте ещё
раз»). Это принятое следствие, оно описывается в миграции README.

Следствие: адрес на другом origin с пользовательским заголовком вызывает
CORS-preflight. Функция задумана для своего origin (`credentials:
'same-origin'`), поэтому это принятое следствие. Оно описывается в README.

## 6. Тесты

**`tests/download.test.js`:**

- запрос уходит с `credentials: 'same-origin'` и заголовком
  `X-Requested-With: XMLHttpRequest` (обновить ожидание существующего теста);
- `401` — отказ с `sessionExpired: true`, `status: 401`, `redirectUrl: null`,
  сообщением из раздела 5; файла нет;
- `404`, `422` и `500` (существующий параметризованный тест) — дополнительно
  `sessionExpired: false`;
- перенаправление — дополнительно `sessionExpired: false`; существующий тест
  «перенаправление, закончившееся ответом 404» параметризуется кодами `404` и
  `401`: в обоих случаях конечный `redirectUrl`, `status: null`,
  `sessionExpired: false`. Это закрепляет, что перенаправление проверяется
  раньше `401`;
- сетевая ошибка — нет и поля `sessionExpired`.

**`tests/download.server.test.js`** (настоящий `fetch` и сервер): сервер
повторяет `auth` Laravel. Без `X-Requested-With: XMLHttpRequest` он отвечает
`302` на `/login`, с этим заголовком — `401`. `downloadFile` получает отказ с
`sessionExpired: true`. Это доказывает, что заголовок действительно уходит.

## 7. README

- `### downloadFile`: заголовок запроса; новая причина отказа `401` с
  `sessionExpired: true` и поля всех причин; пример для Inertia сначала
  проверяет `error.sessionExpired` и показывает `NotificationMessage`
  (`type="warning"`) с текстом страницы, например «Сессия закончилась.
  Обновите страницу.». Затем идёт `redirectUrl`, затем «Попробуйте ещё раз».
  Добавить примечание про CORS-preflight для чужого origin.
- «Обновление с 0.25»: Laravel теперь отвечает на истёкшую сессию `401`, а не
  перенаправлением, а на невалидные параметры выгрузки — `422`, а не
  перенаправлением назад. Страницам, которые переходили по `redirectUrl`,
  нужна ветка `sessionExpired`; невалидные параметры попадают в общую ветку
  отказа.
