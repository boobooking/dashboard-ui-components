# FormTextarea — многострочное поле формы со счётчиком символов

Дата: 2026-11-04

## 1. Цель и рамки

Многострочное поле для текста — сообщения, комментария, списка ключей — дашборды
верстают сами, каждый по-своему (раздел 2). Цель: компонент пакета
`FormTextarea` в том же виде, что `FormInput`: заголовок над полем, красная
точка обязательности, подпись под полем. По пропу над полем показывается
счётчик символов. Счётчик — отдельный внутренний компонент `CharacterCounter`,
чтобы потом поставить его и в другие поля.

Слова в документе: **заголовок** — текст над полем (проп `label`), **подпись** —
текст под полем (проп и слот `description`, см. README «Описание поля»).

В рамках задачи:

- публичный компонент `FormTextarea`;
- внутренний компонент `CharacterCounter`, из пакета не экспортируется;
- тексты счётчика для скринридера в `src/i18n.js`;
- тесты, Playground, README;
- выпуск `0.25.0` (раздел 10).

Вне рамок:

- перевод belarus, overweight и certificates на `FormTextarea` — отдельные задачи;
- ограничение ввода: `maxlength` и обрезка текста;
- выбор способа подсчёта символов (проп или параметр);
- счётчик в других полях пакета, в том числе в `FormInput`;
- общая утилита рамки текстового поля для всех полей пакета (раздел 11).

## 2. Что показало исследование

Просмотрены `~/Code/mars` и `~/Code/payments`. Многострочное поле есть в трёх
местах, и все три разные:

- **belarus, `resources/js/Shared/TextZone.vue`** — формы напоминаний
  (`Pages/Reminders/Create.vue`, `Edit.vue`). Заголовок «Текст сообщения»,
  красная точка, `rows="6"`. Справа в строке заголовка счётчик
  `символы / 279` (`text-xs font-medium text-gray-500`); сверх лимита первое
  число становится `text-red-300`. Ввод не ограничен. `id="message"` зашит,
  две копии на странице разделили бы один `id`.
- **overweight, `resources/js/Pages/Consumers/Edit.vue`** — заголовок
  «Комментарий», `rows="10"`, без точки и счётчика.
- **certificates, `src/resources/js/Pages/Groups/Keys/Create.vue`** — без
  видимого заголовка, `aria-label`, моноширинный шрифт, `rows="16"`,
  `resize-none`, только вертикальная прокрутка; ключи по одному в строке.

Пакет подключён только в cashback, certificates и payments; belarus и
overweight пакетом не пользуются.

В пакете образец — `FormInput` (`src/components/FormInput.vue`): заголовок
`bb:text-sm bb:font-medium bb:leading-5 bb:text-gray-700`, `Dot color="red-pale"`
по `isRequired`, поле `bb:mt-1 bb:block bb:w-full bb:rounded-md bb:border
bb:border-gray-300 bb:bg-white bb:px-3 bb:py-2 bb:text-sm bb:leading-5
bb:shadow-xs bb:focus:focus-ring`, `useId()`, `inheritAttrs: false`, миксин
`withFieldDescription` и внутренний `FieldDescription`.

Ресет пакета (`src/styles/index.css`, слой `components`) задаёт `font: inherit`,
`appearance: none`, снятие кольца `@tailwindcss/forms` на `:focus` и прочее
только для `input` и `button`; `textarea` в нём не упомянута. Preflight Tailwind
пакет не подключает; в приложении с preflight у `textarea` стоит
`resize: vertical`, без него у браузера по умолчанию `resize: both`.

Laravel проверяет длину строки (`max:` и `size:`) через `mb_strlen` — по
символам Unicode (code points). Inertia отправляет значение JSON-ом, перенос
строки остаётся `\n`.

## 3. Решения и их источники

| Решение | Источник |
| --- | --- |
| Новый публичный компонент в виде `FormInput`: заголовок, точка, подпись | владелец |
| Счётчик — внутренний закрытый компонент, поле включает его пропом; потом счётчик может появиться в других местах | владелец |
| Счётчик только считает и показывает, ввод не блокирует | владелец |
| Место счётчика — справа в строке заголовка, всегда, ни от чего не зависит | владелец, макет A |
| Заголовок обязателен и есть всегда | владелец |
| Количество строк задаётся пропом | владелец |
| Поле растягивается, запрета нет | владелец |
| Имена `FormTextarea` и `CharacterCounter` | автор, одобрено владельцем |
| Проп лимита — `characterLimit` | автор по замечанию владельца, одобрено владельцем |
| Символы считаются одним способом — как `mb_strlen` в Laravel, без параметра | автор, одобрено владельцем |
| `rows` по умолчанию 6, как в belarus | автор, показано владельцу |
| Растягивание только по высоте | автор, показано владельцу |
| Вид счётчика: 12 px, `gray-500`; сверх лимита первое число красное | автор, показано владельцу (макет) |
| Скринридер читает счётчик вместе с полем, без объявления на каждую клавишу | автор, показано владельцу |
| Ровно на лимите счётчик не красный: красный только «больше лимита» | автор |
| Текст для скринридера без склонений: «Символов: 112 из 279» | автор |
| Счётчик считает текст в поле, а не `modelValue`: работает без `v-model` и во время IME | автор |
| При переносе заголовка счётчик напротив первой строки | автор |
| Проп `lang`, как у всех компонентов с текстами | автор, по «Правилам API пакета» |
| Выпуск `0.25.0` по образцу ActionButton | автор, показано владельцу |

## 4. API `FormTextarea`

### 4.1. Пример

```vue
<form-textarea
    v-model="message"
    label="Текст сообщения"
    :is-required="markMessageRequired"
    :character-limit="279"
    description="Текст уйдёт в SMS и push-уведомление."
/>

<form-textarea v-model="comment" label="Комментарий" :rows="10" />
```

### 4.2. Пропы и события

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `String` | `""` | Значение поля |
| `label` | `String` | обязателен | Заголовок над полем |
| `isRequired` | `Boolean` | `false` | Красная точка у заголовка |
| `rows` | `Number` | `6` | Высота поля в строках |
| `characterLimit` | `Number` | `null` | Лимит символов; задан — над полем счётчик |
| `description` | `String` | `null` | Подпись под полем, см. README «Описание поля» |
| `lang` | `String` | `null` | `"ru"` или `"en"`, см. README «Языки» |

Слот `description` — как у `FormInput`.

Событие `update:modelValue` уходит на каждый ввод со строкой из поля как есть,
без обрезки пробелов. Значение, изменённое родителем, поле показывает сразу и
без события. Набор через IME отдаёт значение по окончании composition — как
нативный `v-model`, так же, как у `FormInput`. Модификаторы `v-model` в API
не входят. `null` в `modelValue` — пустая строка.

Счётчик считает текст, который сейчас в поле, а не `modelValue`: он
меняется на каждое событие `input`, в том числе без `v-model` у страницы и
во время набора через IME, когда `update:modelValue` ещё не ушло. Смена
`modelValue` родителем меняет и поле, и счётчик. Само событие
`update:modelValue` уходит как у `FormInput` — после composition.

### 4.3. `rows`

- Целое число больше нуля — атрибут `rows` у `<textarea>`.
- Другое значение (0, отрицательное, дробное, не число) отклоняет `validator`
  с предупреждением Vue, поле рисуется с `rows="6"`. `null` и `undefined` —
  без предупреждения, 6.

### 4.4. `characterLimit`

- Целое число больше нуля — над полем счётчик (раздел 6).
- `null`, `undefined` и отсутствие пропа — счётчика нет, без предупреждения.
- Другое значение (0, отрицательное, дробное, не число) отклоняет `validator`
  с предупреждением Vue, счётчика нет, компонент не падает.
- Атрибут `maxlength` поле от пропа не получает. Переданный страницей
  `maxlength` ложится на `<textarea>`, как любой атрибут (4.5).

### 4.5. Атрибуты, `id`, `isRequired`

Как у `FormInput`:

- `inheritAttrs: false`; `class` и `style` — на корень, все остальные атрибуты
  и слушатели (`placeholder`, `name`, `disabled`, `readonly`, `autocomplete`,
  `@blur`, `@keydown`) — на `<textarea>`.
- `id` поля создаётся `useId()`, `for` заголовка указывает на него. `id` от
  страницы заменяет созданный и в поле, и в `for`.
- `aria-describedby` страницы сохраняется; итоговое значение — `id` через
  пробел: страницы, подписи, счётчика (тех, что есть).
- `isRequired` только рисует точку: `required` и `aria-*` поле от него не
  получает.

## 5. Разметка и вид поля

- Корень — `bb-dashboard-ui`, как у `FormInput`.
- Строка заголовка: слева заголовок и точка (классы и отступы как у
  `FormInput`), справа счётчик, если задан `characterLimit`. Счётчик прижат к
  правому краю строки и выровнен по вертикали по центру первой строки
  заголовка. Высота строки заголовка со счётчиком и без него одинаковая.
- Длинный заголовок переносится, счётчик не сжимается и не переносится
  (`bb:shrink-0`), между ними зазор. При переносе счётчик стоит напротив
  первой строки заголовка, а не по центру всего блока.
- `<textarea>` — те же классы рамки, фона, отступов, шрифта, тени и фокуса,
  что у поля `FormInput`, плюс `bb:resize-y`. Ширина — во всю ширину корня,
  высота — по `rows`.
- Подпись под полем — `FieldDescription`, как у `FormInput`.
- Ресет `src/styles/index.css` распространяется на `textarea` так же, как на
  `input`: наследование шрифта и цвета, `appearance: none`, снятие кольца
  `@tailwindcss/forms` на `:focus`. Иначе в голом окружении у поля будет
  шрифт браузера, а в окружении приложения — второе кольцо фокуса.
- Растягивание: только по высоте, в обоих окружениях Playground. Ширина не
  меняется.
- `disabled` и `readonly` — вид браузера и приложения, как у `FormInput`;
  счётчик и подпись остаются и не гаснут.

## 6. `CharacterCounter`

Внутренний компонент, `src/components/CharacterCounter.vue`, из
`src/index.js` не экспортируется. Ничего не знает о textarea: получает текст и
лимит.

| Проп | Тип | Описание |
| --- | --- | --- |
| `text` | `String` | Текст, который считают; `null` — пустая строка |
| `limit` | `Number` | Лимит, целое больше нуля; проверяет поле, которое включает счётчик |
| `id` | атрибут | `id` скрытого текста для скринридера (см. ниже) |
| `lang` | `String` | Язык текста для скринридера |

**Подсчёт.** Число символов Unicode (code points), как `mb_strlen`:
`Array.from(text).length`. Перенос строки — один символ. Обычный эмодзи — один
символ, составной (например, «семья» из нескольких людей) — несколько, ровно
как его посчитает Laravel.

**Вид.** `112 / 279`: число, косая черта, лимит. 12 px, высота строки 16 px,
`gray-500`, цифры одинаковой ширины (`tabular-nums`), чтобы счётчик не дёргался
при наборе. Когда символов больше лимита, первое число красное — цвет
`mark` набора `red-pale` из `src/colors.js` через `colorClass`, тот же красный,
что у точки обязательности. Ровно на лимите и меньше — без красного. Вид
счётчика задан только в этом компоненте; поле вызывает его без своих классов,
кроме раскладки (`shrink-0`) — она остаётся у поля.

**Скринридер.** Видимый `112 / 279` скрыт от скринридера (`aria-hidden`).
Рядом — визуально скрытый текст с `id`: «Символов: 112 из 279» / «Characters:
112 of 279». Поле ссылается на него через `aria-describedby` (4.5), поэтому
скринридер читает счётчик вместе с полем при фокусе и по запросу описания.
`aria-live` нет: объявление на каждую клавишу мешало бы печатать. Сверх лимита
текст тот же, число само показывает превышение.

`id` текста строится от `id` поля: `<id поля>-counter`, как `-description` у
подписи.

**Тексты.** В `src/i18n.js`, в `ru` и `en`, одинаковыми ключами; компонент
берёт их через `withLang`. `FormTextarea` передаёт свой `lang` в счётчик.

## 9. Принятые риски

- Счётчик считает строку как есть, а `TrimStrings` в Laravel обрезает пробелы
  по краям до проверки. Текст с пробелами по краям может быть красным в
  счётчике и пройти проверку сервера.
- Если форма отправляется обычным POST, а не через Inertia, браузер
  превращает перенос строки в `\r\n`, и сервер насчитает на один символ на
  каждый перенос больше. Все три проекта с полем работают через Inertia.
- Составной эмодзи считается за несколько символов, хотя виден один — так же,
  как его посчитает сервер.

## 10. Выпуск

Работа идёт на ветке `feat/form-textarea` от локального `main`. Версия
`0.25.0` — последний коммит ветки после итогового ревью. Слияние и тег
`v0.25.0` — по слову владельца.

## 11. Что остаётся за исполнителем

- Как именно визуально скрыть текст для скринридера (утилита `sr-only` с
  префиксом или своя), если поведение совпадает с разделом 6.
- Ключи `src/i18n.js` и устройство текста с числами (одна строка с
  подстановкой или куски вокруг чисел, как у пагинации).
- Состав и порядок задач плана, демо Playground сверх перечисленного.
- Классы рамки поля повторяют классы `FormInput` и ещё десятка полей пакета.
  Вынести их в одну утилиту `@utility` — отдельная задача; в этой задаче
  `FormTextarea` берёт те же классы, а совпадение вида проверяет Playwright
  (раздел 8).
