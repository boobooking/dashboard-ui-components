# Фокус в `ConfirmationModal`

Дата: 2026-10-16

## 1. Цель и рамки

После выбора пункта «Delete» в меню строки (`DropdownButtonWithAction`)
открывается `ConfirmationModal`, а фокус остаётся на кнопке меню за модалкой.
Enter или пробел открывают меню заново — поверх модалки. Tab уходит на
страницу за модалкой, Escape модалку не закрывает, после закрытия фокус
пропадает на `body`. Нашло это итоговое ревью перехода payments на `0.17.0`.

Цель — модалка подтверждения ведёт себя как диалог: фокус внутри, пока она
открыта, и на прежнем месте после закрытия.

В рамках задачи (выпуск `0.17.1`):

- новый внутренний модуль `src/dialogFocus.js`;
- `Modal.vue` держит фокус открытой модалки, `ConfirmationModal.vue` ставит
  начальный фокус на кнопку отмены и превращает Escape в `actionCanceled`;
- тесты; README; Playground;
- версия `0.17.1` последним коммитом и её публикация;
- обновление payments, cashback и certificates до `^0.17.1`.

Вне рамок:

- две модалки, открытые одновременно, и выпадающие панели внутри модалки:
  ни один проект так не делает (раздел 14);
- родной `<dialog>` с `showModal()`: владелец выбрал доработку нынешнего
  `Modal` (раздел 3);
- вид кнопок модалки: классы не меняются (раздел 4, пункт 6);
- меню `PopoverPanel` / `PopoverMenu`: оно ведёт себя правильно (раздел 2).

## 2. Что показало исследование

**Воспроизведение.** Отдельная страница на исходниках `0.17.0`:
`DropdownButtonWithAction` с действиями «Edit» (ссылка) и «Delete»
(`onSelect` открывает модалку) и `ConfirmationModal` типа `dangerous`.
Chrome, только клавиатура: Tab до стрелки меню, Enter, стрелка вниз до
«Delete», Enter.

| Шаг | Результат |
| --- | --- |
| модалка открыта | фокус на кнопке меню (`popovertarget`), не в модалке |
| Enter | меню открыто, в центре меню `elementFromPoint` даёт меню, не модалку |
| Escape, Escape | меню закрыто, модалка осталась открытой |
| Tab | фокус на кнопке страницы за модалкой |

**Причины.**

1. `Modal.vue` фокусом не управляет: не переносит его внутрь, не удерживает,
   не возвращает, Escape не слушает. README записывает это ограничением
   (раздел «Стили», последний абзац).
2. Пункт меню выполняет `onSelect`, после него `PopoverPanel` закрывает
   панель (`closeOnClick`) вызовом `hidePopover()`. Браузер по правилам
   Popover API возвращает фокус на кнопку, которая открыла панель, — если
   фокус был внутри панели. Это происходит синхронно, внутри того же клика.
3. Панель меню лежит в верхнем слое браузера, модалка — обычный блок с
   `z-20`. Открытое заново меню поэтому рисуется поверх модалки.
4. Страница за модалкой не заблокирована: затемнение ловит только мышь.

**Проверка гипотезы.** На той же странице фокус переводился на «Cancel»
после отрисовки открытой модалки (наблюдатель с `flush: "post"` и
`nextTick`). Итог: фокус на «Cancel», меню закрыто; Enter нажимает «Cancel»
(`actionCanceled`), меню не открывается. Браузер к этому моменту фокус уже
вернул (пункт 2), а событие `toggle` панели приходит позже и фокус не
трогает: у меню нет `returnFocus`. После закрытия фокус оказался на `body` —
возвращать его нужно отдельно.

**Проекты.** payments, cashback и certificates стоят на `^0.17.0`, у них
10 модалок подтверждения. Ни один проект фокус модалки сам не ставит
(поиск `.focus(`, `autofocus`, `Escape` пуст). Все обработчики
`action-canceled` только закрывают модалку и сбрасывают выбранную запись.

| Решение | Источник |

## 4. Поведение `ConfirmationModal`

1. **Открытие.** Как только модалка отрисована открытой, фокус на кнопке
   отмены. Enter подряд после открытия не выполняет действие.
2. **Tab и Shift+Tab** переводят фокус по кнопкам модалки по кругу, в порядке
   DOM: кнопка действия, затем кнопка отмены. На экране кнопки стоят в обратном
   порядке (`flex-row-reverse`), поэтому Tab идёт слева направо: отмена →
   действие → отмена. Фокус вне модалки (например, после клика по затемнению)
   — Tab ставит его на первую кнопку, Shift+Tab — на последнюю.
3. **Escape** — событие `actionCanceled`, как у кнопки отмены. Модалку
   закрывает родитель, как сейчас. Закрытая модалка Escape не слушает.
4. **Закрытие** (родитель ставит `isOpen` в `false`) и размонтирование
   открытой модалки. Фокус возвращается на элемент, где он был при открытии,
   если одновременно:
   - фокус потерян (`body` или `null`) или стоит внутри модалки — фокус,
     который страница поставила в другое место, не забирается;
   - прежний элемент ещё в документе (`isConnected`) — после удаления строки
     его может уже не быть.
   Возврат — `focus({ preventScroll: true })`, как в `PopoverPanel`.
   Прежний элемент — `body` или `null`: возвращать некуда.
5. Не меняются: вид, анимации, пропсы и события `ConfirmationModal`,
   затемнение и клики по нему.
6. **Видимое следствие.** У кнопки отмены классы `focus:ring-2
   focus:ring-offset-2 focus:ring-indigo-500`, поэтому при каждом открытии —
   и мышью тоже — вокруг неё видно индиго-кольцо. Это одобрено (раздел 3).

## 5. `src/dialogFocus.js`

Внутренний модуль, как `menuFocus.js` и `dayFocus.js`; из `src/index.js`
не экспортируется.

```js
// Фокус открытого диалога: начальный — на элемент с data-dialog-focus,
// без него — на первый; Tab и Shift+Tab — по кругу внутри; Escape —
// onEscape. Возвращает функцию, которая снимает слушатель и возвращает
// фокус туда, где он был до вызова.
export function holdDialogFocus(panel, onEscape)
```

- **Элементы фокуса** — `a[href], button:not(:disabled)` внутри `panel`, в
  порядке DOM. Других у модалок пакета нет.
- **При вызове**: прежний элемент — `document.activeElement`; фокус —
  на `panel.querySelector('[data-dialog-focus]')`, без него — на первый
  элемент; нет ни одного — фокус не трогается.
- **Слушатель** `keydown` на `document` в фазе захвата — по той же причине,
  что у `menuFocus.js`: расширения браузера останавливают `keydown` на `body`.
  - Tab: элементов нет — ничего. Иначе `preventDefault()` и фокус на
    следующий элемент по кругу (Shift+Tab — на предыдущий); фокус вне
    `panel` — на первый (Shift+Tab — на последний). Каждый Tab ведёт модуль,
    а не только переход с краёв: в Safari Tab по умолчанию пропускает кнопки
    и увёл бы фокус из модалки, а алгоритм тот же, что у стрелок в меню.
  - Escape: `onEscape()`, без `preventDefault()`.
  - Остальные клавиши не трогаются.
- **Возвращённая функция**: снимает слушатель; возвращает фокус по правилам
  раздела 4, пункт 4. Повторный вызов ничего не делает.

## 6. `Modal.vue` и `ConfirmationModal.vue`

**`Modal.vue`**:

- `ref="panel"` на блоке `role="dialog"`;
- `emits: ["escape"]` — внутреннее событие, только для `ConfirmationModal`;
- наблюдатель `isOpen` с `flush: "post"`: `true` — `holdDialogFocus(panel,
  () => this.$emit("escape"))`, `false` — снять; `mounted` — то же, если
  модалка открыта сразу; `beforeUnmount` — снять. Держатель один: повторное
  «держать» без «снять» ничего не делает;
- `document` трогается только в `mounted`, наблюдателе и `beforeUnmount` —
  при SSR ни одно из них не выполняется.

**`ConfirmationModal.vue`**:

- `data-dialog-focus` на кнопке отмены;
- `@escape="$emit('actionCanceled')"` на `<modal>`.

Разметка, классы, пропсы и события для проектов не меняются.

## 7. Тесты

vitest + happy-dom, в стиле `tests/menuFocus.test.js`.

**`tests/dialogFocus.test.js`** — таблицей случаев, где их несколько:

- начальный фокус: на `data-dialog-focus`; без метки — на первый элемент;
  без элементов — фокус не меняется;
- Tab: с первого — на второй, с последнего — на первый, вне панели — на
  первый; Shift+Tab: с первого — на последний, вне панели — на последний;
  у перехваченного Tab `defaultPrevented`; отключённая кнопка пропускается;
- Escape вызывает `onEscape` один раз и без `preventDefault`; Enter, стрелки
  и буквы не перехватываются;
- возврат: фокус в панели — на прежний элемент; фокус на `body` — на
  прежний; фокус на другом элементе страницы — остаётся там; прежний
  элемент удалён — фокус не трогается; прежний был `body` — не трогается;
- после возврата Tab и Escape не перехватываются; повторный вызов ничего
  не делает.

**`tests/ConfirmationModal.test.js`** — новые случаи (`attachTo:

- смонтирована открытой: фокус на кнопке отмены;
- Escape в открытой — одно событие `actionCanceled`, в закрытой — ни одного;
- закрытие: фокус возвращается на кнопку, которая была в фокусе до открытия;
- размонтирование открытой: Escape после него событий не даёт, фокус на
  прежней кнопке.

`tests/ssr.test.js`, `tests/hydration.test.js`, `tests/i18n.test.js`,
`tests/exports.test.js` не меняются и остаются зелёными. `npm test` —
