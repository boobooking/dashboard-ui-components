# DropdownButtonWithAction: кнопка из списка действий и цвета пунктов

Дата: 2026-10-09

## 1. Цель и рамки

Сейчас у `DropdownButtonWithAction` две части с разным устройством.
Основную кнопку проект рисует сам в слоте `button`, а меню пакет строит
из пропа `actions`. Цветов у пункта меню два: обычный и красный
(`danger: true`).

Цель: проект передаёт только список действий, а вид кнопки компонент
определяет сам:

- первое действие — основная кнопка, остальные — в меню за стрелкой;
- одно действие — кнопка без стрелки и меню;
- у действия три цвета: обычный, жёлтый, красный. Цвет первого действия
  красит кнопку, цвет пункта меню — только этот пункт;
- основное действие, как и пункт меню, выполняет сам пакет: проект больше
  не зависит от разметки кнопки.

В рамках задачи (выпуск `0.15.0` на ветке `feat/hamburger-menu`, вместе с
`HamburgerMenu` и переводом выпадающих частей на Popover API):

- пункт с полем `color` вместо `danger` — общий для `DropdownButtonWithAction`
  и `HamburgerMenu`;
- основная кнопка из первого действия, раскладка по числу действий;
- удаление слота `button` и поля `danger` с предупреждениями в режиме
  разработки;
- тесты, Playground, README;
- приёмка в Chrome и Safari, итоговое ревью, версия `0.15.0` последним
  коммитом ветки.

Вне рамок:

- перевод страниц certificates, cashback и payments — свои задачи в их
  репозиториях (раздел 9 даёт образцы замены);
- вид пунктов списка `SelectSingle` — не меняется;
- кнопка ☰ `HamburgerMenu` — не красится: правило «первое действие —
  кнопка» есть только у `DropdownButtonWithAction`;
- другие цвета, иконки, неактивное состояние кнопки.

## 2. Что показало исследование

**Кнопки в проектах.** Пять страниц в трёх проектах:

| Проект, версия пакета | Страница | Основная кнопка (слот `button`) | Меню |
| --- | --- | --- | --- |
| certificates, `^0.14.0` | `Users/Index.vue` | `<Link>` «Редактировать» | «Поменять пароль» (переход), «Удалить» (`danger`) |
| certificates | `Groups/Index.vue` | `<Link>` «Посмотреть» | нет |
| certificates | `Groups/Certificates.vue` | `<Link>` «Добавить ключи» | нет |
| certificates | `Groups/Messages.vue` | `<span>` «Отправить заново» | «Зафиксировать как неотправленное» (действие) |
| cashback, старый API со слотом `actions` | `Users/Index.vue` | `<Link>` «Редактировать» | «Удалить» (красный) |
| payments, `^0.9.0` | `Users/Index.vue`, `PaymentAgents/Index.vue` | `<Link>` «Edit» | «Change password», «Delete» (красный) |

У всех `<Link>` в слоте одни и те же классы:
`block px-4 py-2 text-sm font-medium text-gray-700`.

**Замечание исполнителя certificates.** «Действие на кнопке из дропдауна
полагается на разметку пакета. Если релиз пакета её поменяет, действие
молча перестанет работать». Речь о `Groups/Messages.vue`. Основное действие
там — действие, а не переход. У основной кнопки пакета нет своего события,
а `<span>` в слоте нажатия с клавиатуры не получает: Enter и пробел
достаются самой `<button>`. Поэтому страница вешает `v-on:click` на корень
компонента, а `retryFromDropdown` засчитывает клик, только если
`event.currentTarget.firstElementChild.contains(event.target)`. Иначе
говоря, страница полагается на то, что основная кнопка — первый элемент
корня. Если пакет её обернёт или переставит, условие перестанет
срабатывать без всякой ошибки.

**Ссылка внутри кнопки.** На остальных страницах в слот кладут `<Link>`,
и ссылка оказывается внутри `<button>` пакета. По стандарту HTML так
вкладывать нельзя.

**Цвета в пакете.** У `SmallBadge` цвет задаётся пропом `color` с именами
цветов, среди них `'yellow'` и `'red'`. Мягкие тона — светлый фон и тёмный
текст того же цвета — у `SmallBadge`, `NotificationMessage` и
`ErrorMessages`. Насыщенные — у кнопки `ConfirmationModal` и у нынешнего
красного пункта меню (`bg-red-400`, белый текст).

**Углы панели.** У `[popover]` браузер по умолчанию ставит `overflow: auto`,
поэтому панель обрезает содержимое по своему скруглению. Подсветка первого
и последнего пункта повторяет углы панели без отдельного класса.

## 4. API

### 4.1. Пример

Страница администраторов certificates после перевода:

```vue
<dropdown-button-with-action
    :actions="[
        { label: 'Редактировать', href: route('user.edit', { user: row.getId() }) },
        { label: 'Поменять пароль', href: route('user.password.edit', { user: row.getId() }) },
        { label: 'Удалить', color: 'red', onSelect: () => prepareUserDelete(row) },
    ]"
/>
```

### 4.2. Пункт

| Поле | Тип | Смысл |
| --- | --- | --- |
| `label` | `String`, обязательно, непустой | Текст кнопки или пункта меню |
| `href` | `String`, непустой | Переход |
| `onSelect` | `Function` | Действие: вызывается без аргументов |
| `color` | `'yellow'` или `'red'` | Цвет; без поля — обычный |

Правила формы — прежние: у пункта ровно одно из `href` и `onSelect`; поле
отсутствует, если его значение `undefined` (ключа нет или он равен
`undefined`). `color` допустим у пунктов обоих видов. Поле `danger` больше
не входит в формат (раздел 4.6). Другие поля компонент не читает и не
проверяет.

Формат общий для `DropdownButtonWithAction` и `HamburgerMenu`: цвета пунктов
появляются в обоих меню.

### 4.3. Раскладка по числу действий

Действия — элементы `actions`, которые являются объектами (не `null`);
остальные элементы пропускаются, а не массив и `null` — пустой список,
как и сейчас.

- **Нет действий** — компонент ничего не рисует.
- **Одно** — одна кнопка, скруглённая с обеих сторон, без стрелки и меню.
- **Два и больше** — первое действие становится основной кнопкой, стрелка
  справа открывает меню со вторым и следующими действиями в их порядке.

Список может меняться, пока компонент на странице. Если при открытом меню
в нём осталось меньше двух действий, меню пропадает так же, как сейчас
пропадает меню без пунктов: родитель получает `update:modelValue` со
значением `false`.

### 4.4. Основная кнопка

Основная кнопка работает как пункт меню:

- **`href`** — ссылка пакета `<a href>`. Обычный клик уходит в `navigate`
  плагина `dashboardUi` через `followLink` миксина `withNavigation`; клик
  с Cmd, Ctrl или Shift и средняя кнопка остаются браузеру; без `navigate` —
  обычная ссылка.
- **`onSelect`** — `<button type="button">`. Клик, а с клавиатуры Enter и
  пробел, вызывают `onSelect` один раз без аргументов. Результат `onSelect`
  возвращается обработчику клика: исключение и отказ Promise получает
  обработчик ошибок Vue, как у пунктов меню.
- Пункт без непустого строкового `href` — `<button>`; если у него нет и
  функции `onSelect` (такой пункт отмечает валидатор, раздел 4.6), клик
  по кнопке ничего не делает.

Проект больше не ловит клик основной кнопки сам: события клика у компонента
нет, и зависеть проекту не от чего.

### 4.5. Цвет

Цвет первого действия красит основную кнопку вместе со стрелкой. Цвет
пункта меню красит только этот пункт. Пример: первое действие обычное,
в меню — красное «Удалить»: кнопка белая, «Удалить» в меню красное.
Единственное действие «Delete» с `color: 'red'` — одна красная кнопка.

### 4.6. Пропсы, событие, проверки

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `actions` | `Array` | `[]` | Действия, раздел 4.2 |
| `modelValue` | `Boolean` | `false` | Открыто ли меню |
| `lang` | `String` | язык плагина | `"ru"` или `"en"` |

Событие `update:modelValue` — без изменений: только когда меню открыл или
закрыл сам компонент или браузер. При одном действии меню нет, и
`modelValue` ни на что не влияет.

Проверки только предупреждают и данные не исправляют: компонент не падает
ни на каком значении.

- Валидатор `actions` отклоняет пункт с неверным `color` (не `undefined`,
  не `'yellow'` и не `'red'`) и пункт с полем `danger` (не `undefined`).
  Такой пункт рисуется обычным.
- Пункт с полем `danger` в режиме разработки даёт предупреждение,
  называющее замену: «[dashboard-ui-components] DropdownButtonWithAction:
  поле danger убрано, красный пункт — color: 'red'». Оно выводится один раз
  на экземпляр компонента — когда такой пункт встретился впервые, при
  создании или после смены `actions`. Список, записанный прямо в шаблоне,
  меняется при каждой перерисовке родителя: без этого ограничения
  предупреждение повторялось бы на каждую. У `HamburgerMenu` — то же,
  со своим именем.
- Слот `button`: если проект его передаёт, слот не рисуется, а в режиме
  разработки при создании компонента уходит предупреждение
  «[dashboard-ui-components] DropdownButtonWithAction: слот button убран,
  основная кнопка — первый пункт actions».
- Предупреждение о слоте `actions` из `0.14` остаётся.

Как и у предупреждения о слоте `actions`, проверку `process.env.NODE_ENV`
подменяет бандлер проекта: в продакшен-сборке предупреждений нет.

## 5. Вид

| | Обычный | Жёлтый | Красный |
| --- | --- | --- | --- |
| **Кнопка** — основная часть и стрелка | как сейчас: фон белый, рамка `gray-300`, текст `gray-700`, у стрелки `gray-500`; при наведении `gray-50` | фон `yellow-100`, рамка `yellow-300`, текст `yellow-800`; при наведении `yellow-200` | фон `red-50`, рамка `red-300`, текст `red-700`; при наведении `red-100` |
| **Пункт меню** | как сейчас: текст `gray-700`; под фокусом фон `gray-100`, текст `gray-900` | текст `yellow-800`; под фокусом фон `yellow-100` | текст `red-700`; под фокусом фон `red-50` |

- Текст основной кнопки — `px-4 py-2 text-sm font-medium`, те же классы,
  что сейчас у `<Link>` проектов в слоте: обычная кнопка в проектах на вид
  не меняется.
- Стрелка — как сейчас (`px-2 py-2`, значок 20 px, `-ml-px`, обёртка
  `bb:flex`); у цветной кнопки текст стрелки — цвета основной части, рамки
  обеих частей одного цвета, поэтому граница между ними того же цвета.
- Фокус с клавиатуры: у стрелки — как сейчас (`focus:z-10`, кольцо
  `ring-1 ring-indigo-500`, рамка `indigo-500`), основная кнопка получает
  такое же. Кольцо одного цвета на всех трёх цветах кнопки.
- Корень — как сейчас: `inline-flex`, `rounded-md`, `shadow-xs`.
  Скругление частей: одна кнопка — `rounded-md`, основная часть при
  стрелке — `rounded-l-md`, стрелка — `rounded-r-md`.

Подсветка пункта меню — по-прежнему фокус, который ставят и стрелки,
и мышь; hover-стилей у пунктов нет. Классы пишутся литералами с префиксом
`bb:` — правило `tests/utilityPrefix.test.js`.

## 6. Устройство

- `src/menuItems.js` — проверка пункта (`isMenuItem`) получает `color`
  и отклоняет `danger`; здесь же — проверка «есть ли в списке пункт
  с `danger`» для предупреждения. Модуль по-прежнему общий для
  `DropdownButtonWithAction`, `HamburgerMenu` и `PopoverMenu`.
- `src/components/PopoverMenu.vue` — классы пункта по `color` вместо
  `danger`; остальное без изменений.
- `src/components/DropdownButtonWithAction.vue` — корень с `v-if` по
  наличию действий; основная кнопка из первого действия: `<a>`
  с `withNavigation` или `<button>`, классы по его `color`; `<popover-menu>`
  получает действия со второго и стрелку в цвете первого. Слота `button`
  нет; предупреждения раздела 4.6.
- `src/components/HamburgerMenu.vue` — предупреждение о `danger`.

Стрелку по-прежнему рисует `DropdownButtonWithAction` в слоте `trigger`
`PopoverMenu`, механика меню — `PopoverPanel`; они не меняются.

**Playground** (раздел `DropdownButtonWithAction`):

- меню с обычным, жёлтым и красным пунктом;

**Тесты.**

- Основная кнопка-переход: обычный клик уходит в `navigate` плагина,

  родитель узнаёт о закрытии.
- Предупреждения о слоте `button`, о `danger` (при создании и после смены
  `actions`, один раз на экземпляр) и неверном `color`; без них — тишина.
- Прежние тесты, где кнопку задаёт слот `button`, переходят на `actions`;
  фикстуры `tests/ssrFixtures.js` и тесты `tests/i18n.test.js` — тоже.

**Приёмка.** В Chrome — исполнитель, в Safari — владелец: Playground и
окружение приложения (`host.html`). Пункты: три цвета кнопки и пунктов
на вид как в одобренной схеме; одна кнопка без стрелки; основное
действие-переход и действие-функция мышью и с клавиатуры (Tab, Enter,
пробел); кольцо фокуса на основной кнопке; меню открывается и ходит
стрелками как раньше.

## 9. Образцы замены для проектов

| Было | Стало |
| --- | --- |
| слот `button` с `<Link :href="…">Редактировать</Link>` и меню в `actions` | `{ label: 'Редактировать', href: … }` первым пунктом `actions` |
