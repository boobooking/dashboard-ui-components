# NotificationMessage поверх содержимого страницы

Дата: 2026-11-24

## 1. Цель и рамки

У корня `NotificationMessage` нет `z-index`. Среди позиционированных элементов
он рисуется в порядке DOM, и README просит ставить компонент в разметке
последним. Внутри `PageCard` это невыполнимо: крестик карточки
(`CrossButton`, `bb:absolute`) стоит в разметке после слота. Если уведомление
лежит в слоте, крестик карточки рисуется поверх уведомления и перехватывает клик
по его крестику: клик закрывает карточку, а не уведомление. certificates
обходит это классом `z-10` на каждом уведомлении в `Groups/Card.vue`. Владелец
решил исправить это в библиотеке: уведомление само рисуется поверх содержимого
страницы.

В рамках задачи:

- корень `NotificationMessage` получает `bb:z-10`;
- тесты, Playground, README;
- выпуск патча 0.26.2 (решение владельца).

Вне рамок:

- уборка `z-10` в certificates — отдельный шаг после выпуска;
- уровень модалки (`z-20`) и верхний слой выпадающих меню не меняются.

## 2. Что показало исследование

- `src/components/NotificationMessage.vue:3`: корень `bb-dashboard-ui bb:fixed
  bb:inset-0 bb:flex bb:items-start bb:justify-end bb:p-6
  bb:pointer-events-none`, без `z-index`.
- `src/components/PageCard.vue:25,31-34`: слот, после него `cross-button` с
  `bb:absolute bb:top-0 bb:right-0 bb:mt-6 bb:mr-4`.
- `src/components/Modal.vue:5`: корень `bb:z-20`.
- `src/components/PopoverPanel.vue`: выпадающие меню открываются в верхнем слое
  браузера (top layer), то есть выше любого `z-index`. Их подложка прозрачна для
  кликов, поэтому меню перекрывает уведомление только там, где панель
  меню над ним. README сейчас ошибочно приписывает меню подложку `z-20`.
- `src/components/SelectDate.vue:70`: ластик `bb:z-10` внутри фильтра.
- README, раздел `NotificationMessage`: «У корня нет `z-index`… ставьте
  компонент в разметке страницы последним… страница может поднять его своим
  классом, например `class="z-30"`».
- certificates `Groups/Card.vue`: четыре уведомления с `class="z-10"` или
  `class="text-left z-10"` и комментарием о крестике `PageCard`. Ревью Codex
  воспроизвело перехват клика при 1440×900.

## 3. Подходы

| Подход | Итог |
| --- | --- |
| `bb:z-10` на корне уведомления | выбран: выше обычного содержимого страницы и крестика `PageCard`, ниже модалки (`z-20`); меню и так в верхнем слое браузера. Уведомление под открытой модалкой остаётся скрытым, как описано в README |
| `bb:z-30` — над модалкой | отброшен: README сознательно держит уведомление под модалкой; уведомление поверх затемнения модалки — изменение поведения без запроса |
| Оставить как есть, страница ставит `z-10` сама | отброшен владельцем: решение должно быть в библиотеке |

## 5. Поведение

- Корень: `bb-dashboard-ui bb:fixed bb:inset-0 bb:z-10 bb:flex bb:items-start
  bb:justify-end bb:p-6 bb:pointer-events-none`. Остальная разметка и
  поведение не меняются.
- Уведомление внутри слота `PageCard` рисуется поверх крестика карточки. Клик по
  крестику уведомления закрывает уведомление, карточка остаётся.
- Под открытой модалкой (`z-20`) уведомление скрыто, как раньше. Открытое меню
  в верхнем слое браузера перекрывает уведомление только своей панелью.
- `class` страницы на корне по-прежнему может поднять уровень (`z-30`).

## 6. Тесты

- **`tests/NotificationMessage.test.js`:** у корня есть класс `bb:z-10`.
- **Playwright** (новый `e2e/notificationLayer.e2e.js`, обе страницы
  Playground, Chromium и WebKit). Демо — отдельная карточка в разделе
  `PageCard` (раздел 7), устроенная так, чтобы крестик уведомления лежал над
  крестиком карточки. Тест при 1440×900 прокручивает страницу так, что верх
  карточки стоит на `y=10`, нажимает кнопку показа уведомления, кликает мышью
  по центру крестика уведомления и проверяет: уведомление скрыто, журнал
  `navigate` Playground (`lastNavigation`, строка «Последний переход») пуст.
  Без `bb:z-10` этот же тест падает: клик попадает в крестик карточки, и в
  журнале появляется переход на `fallback-url`. Это проверяется до
  исправления (RED). Адрес страницы как признак не годится: в Playground
  `navigate` его не меняет.

## 7. Playground и README

- Playground, раздел `PageCard`: вторая карточка `page-card` с `fallback-url`
  (крестик есть), `width="7xl"` и `max-width: 88rem`. По пробе Codex этого
  хватает, чтобы при 1440×900 крестик уведомления пришёлся на крестик карточки.
  Внутри слота — кнопка «Показать уведомление» и `notification-message`.
- README `### NotificationMessage`: абзац про `z-index` переписать. У корня
  `z-10`: уведомление рисуется поверх содержимого страницы, в том числе поверх
  крестика `PageCard`, когда лежит в его слоте. Модалка (`z-20`) выше него.
  Выпадающие меню открываются в верхнем слое браузера и перекрывают
  уведомление только своей панелью. Совет ставить компонент последним остаётся — для элементов с тем же
  `z-10`. `class="z-30"` по-прежнему поднимает его выше.
- README «Обновление с 0.25» (или новый раздел «Обновление с 0.26»): `z-10`,
  которым страницы поднимали уведомление, больше не нужен.
