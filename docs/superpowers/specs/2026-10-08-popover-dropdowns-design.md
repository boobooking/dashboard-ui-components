# Выпадающие части пакета на Popover API: PopoverPanel

Дата: 2026-10-08

## 1. Цель и рамки

Меню `DropdownButtonWithAction` и `HamburgerMenu` стоят на Popover API
(приватный `PopoverMenu`). Список `SelectSingle` (через приватный
`DropdownButton`) и календарь `PickDay` (два поля `SelectDateInterval`)
по-прежнему открываются через приватный `Popup`: блок `absolute` под полем
с `z-20` и прозрачный `Overlay` на весь экран, который ловит клик вне и
Escape.

Цель: все выпадающие части пакета работают на одной технологии — Popover
API — и на одном механизме открытия, закрытия и места у кнопки. Механика
живёт в одном приватном компоненте `PopoverPanel`; меню, список и календарь
строятся над ним и задают только свою кнопку, содержимое и вид панели.
`Popup` и `Overlay` удаляются.

В рамках задачи (выпуск `0.15.0` вместе с уже сделанным `HamburgerMenu`):

- приватный `PopoverPanel` — механика, перенесённая из `PopoverMenu`;
- `PopoverMenu`, `DropdownButton` и `PickDay` — на `PopoverPanel`;
- `SelectSingle` отдаёт навигацию стрелками `PopoverPanel`;
- `placePopover` — выравнивание по левому краю кнопки с разворотом;
- удаление `Popup.vue`, `Overlay.vue` и `tests/Overlay.test.js`;
- тесты, playground, README;
- итоговое ревью и выпуск `0.15.0` на ветке `feat/hamburger-menu`.

Вне рамок:

- публичный API `SelectSingle`, `SelectDateInterval`,
  `DropdownButtonWithAction`, `HamburgerMenu` — не меняется;
- клавиатура календаря Pikaday: его стрелки слушают `document` на
  всплытии, и расширение Safari владельца их глушит; сейчас клавиатура
  календаря выключена (`keyboardInput: false`), так и остаётся;
- роли доступности списка `SelectSingle` (`listbox`, `option`) — сейчас
  их нет, и задача их не добавляет;
- решение по `Dot` — отдельно.

## 2. Что показало исследование

- `Overlay` использует только `Popup`; `Modal` рисует свой фон и `Overlay`
  не импортирует. `Popup` используют `DropdownButton` и `PickDay`.
  `DropdownButton` использует только `SelectSingle`.
- `DropdownButton` открывает список кликом по кнопке через `v-model`
  `isOpen`, поднимает кнопку `z-20` над оверлеем и после закрытия
  возвращает фокус на кнопку, если он был внутри: Safari по клику фокус
  на кнопку не ставит.
- `SelectSingle` сам вешает `moveMenuFocus` на свой список по наблюдателю
  `isOpen` и сам закрывает список, если пункты пропали (`hasItems`).
- `PickDay` — кнопка с полем ввода внутри (поле отключено, пока календарь
  открыт), ластик и `Popup` с контейнером Pikaday (`bound: false`,
  `keyboardInput: false`); выбор даты закрывает календарь.
- Механика Popover API — в `PopoverMenu`: `useId`, слот `trigger`
  с `{ id, popovertarget }`, `applyMenuState`, гашение ответного события,
  состояние по факту в `onToggle`, наблюдатель пропавших пунктов
  с `flush: "post"`, `placePopover` в `beforetoggle`,
  `closeOnScrollAndResize`, `moveMenuFocus`, `stopListening`.
- `v-bind="$attrs"` в пакете есть только в `Popup.vue`; проверка префикса
  (`tests/utilityPrefix.test.js`) разрешает его с комментарием про
  `Popup.vue`.
- В `PickDay` поле ввода вложено в кнопку через `<label>`. Клик по полю
  достаётся самому полю и `<label>`: у них своё поведение активации, и
  до кнопки активация не доходит. Сейчас открывает Vue-обработчик `@click`
  кнопки, который ловит всплывший клик. С `popovertarget` вместо него клик
  по полю календарь не открыл бы. Проверено в Chrome на разметке
  `PickDay`: клик по полю внутри кнопки с `popovertarget` панель
  не открывает, фокус уходит в поле; с `pointer-events: none` на
  `<label>` клик достаётся кнопке, панель открывается.
- `:class="panelClass"` проверка префикса отклоняет: в `:class` она
  принимает только литералы (и `$attrs.class`), а на имя переменной
  отвечает «форма Identifier в :class не проверяется».
- Утилита отображения (`bb:flex` и подобные) на самом элементе
  `[popover]` перебивает браузерное `display: none` закрытого popover:
  стили страницы сильнее стилей браузера. Закрытая панель с такой
  утилитой была бы видна.

## 3. Решения и их источники

| Решение | Источник |
| --- | --- |
| Список и календарь — на Popover API, `Popup` и `Overlay` удаляются | владелец (задача после `HamburgerMenu`) |
| Прокрутка страницы и изменение размера окна закрывают список и календарь, как меню | выбор владельца |
| Общий приватный `PopoverPanel` для меню, списка и календаря (подход A) | выбор владельца из трёх подходов |
| Вид и поведение для пользователя — по таблицам раздела 7 | согласовано в дизайне |
| Тесты, приёмка, выпуск — по разделам 9–12 | согласовано в дизайне |
| Работа на ветке `feat/hamburger-menu`, одна версия `0.15.0` | согласовано в дизайне |
| Клик внутри панели закрывает её по пропу `closeOnClick`, а не методом `close()` | уточнение при записи спеки: обработчик должен стоять на самой панели, чтобы разметка меню не изменилась (раздел 4.4) |
| Клики по полю `PickDay` достаются кнопке: `<label>` с полем — `bb:pointer-events-none` | ревью спеки (раздел 6.3) |
| Проверка префикса принимает `:class="panelClass"` только в `PopoverPanel.vue` | ревью спеки (раздел 4.2) |

## 4. `PopoverPanel` (приватный)

Файл `src/components/PopoverPanel.vue`. Механика переносится из
`PopoverMenu` без переписывания: комментарии, исправления и порядок
действий сохраняются; меняются только комментарии, которые после переноса
стали бы ложными.

### 4.1. Интерфейс

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `Boolean` | `false` | Открыта ли панель |
| `hasContent` | `Boolean` | `true` | Есть ли что показывать |
| `align` | `String` | `"end"` | `"end"` — правый край панели по правому краю кнопки; `"start"` — левый край по левому краю кнопки, с разворотом (раздел 5) |
| `maxWidth` | `Number` | `null` | Наибольшая ширина панели, px |
| `arrows` | `Boolean` | `false` | Стрелки и мышь ведут фокус по кнопкам и ссылкам панели (`moveMenuFocus`) |
| `findSelected` | `Function` | `() => null` | Выбранный пункт, от которого считают стрелки, пока фокус вне панели |
| `closeOnClick` | `Boolean` | `false` | Клик внутри панели закрывает её |
| `panelClass` | `String` | `""` | Вид панели |
| `panelRole` | `String` | `null` | Роль панели; при `"menu"` — ещё `aria-orientation="vertical"` |

`align` — с валидатором `["start", "end"]` (правило пакета для
пропов-перечислений).

Событие `update:modelValue` — с прежним смыслом меню: входящее значение
только принимается, без ответного события; о каждом открытии и закрытии
самой панелью (кнопка, клик вне, Escape, клик внутри при `closeOnClick`,
прокрутка, размер окна, пропавшее содержимое) родитель узнаёт один раз.

Слоты:

- `trigger` с пропсами `{ id, popovertarget }` — кнопка вешает их на себя
  двумя явными атрибутами `:id="trigger.id"
  :popovertarget="trigger.popovertarget"` (`v-bind="trigger"` отклоняет
  проверка префикса);
- по умолчанию — содержимое панели.

### 4.2. Разметка

- Корень — `<span class="bb:relative">` с `v-if="hasContent"`;
  отображение и размеры задаёт вызывающий компонент классом
  на `<popover-panel>`.
- В корне — слот `trigger` и панель `popover="auto"` с `:id`,
  `aria-labelledby` = `id` кнопки, ролью из `panelRole` и классами
  `bb:m-0 bb:inset-auto` плюс `panelClass`.
- В `panelClass` не бывает утилит отображения (`bb:flex`, `bb:block`,
  `bb:grid` и подобных): они перебили бы `display: none` закрытой панели
  (раздел 2). Раскладку содержимого задаёт элемент внутри панели.
- `:class="panelClass"` — узкое исключение проверки префикса
  (`tests/utilityPrefix.test.js`): имя `panelClass` в `:class`
  принимается только в файле `PopoverPanel.vue`. Классы туда приходят
  из атрибута `panel-class` вызывающих компонентов, а этот атрибут
  проверка уже читает как проп классов (`isClassProp`) — каждая утилита
  в нём должна быть литералом с префиксом. В любом другом файле то же
  `:class="panelClass"` по-прежнему отклоняется. Для этого анализатор
  получает имя проверяемого файла.

### 4.3. Поведение

Без изменений против нынешнего `PopoverMenu`:

- открытие и закрытие по `popovertarget`; приведение к `modelValue`;
  гашение ответного события; состояние — по фактическому состоянию панели,
  а не по `newState` события `toggle`;
- место — `placePopover` в `beforetoggle` по самой кнопке из слота
  (найденной по `id`), с `align` и `maxWidth`; вниз или вверх — где больше
  места; высота ограничена этим местом, длинное содержимое прокручивается
  внутри панели;
- прокрутка вне панели и изменение размера окна закрывают её; прокрутка
  внутри — нет;
- при `arrows` — `moveMenuFocus(панель, findSelected)`, пока панель
  открыта;
- `hasContent` стал `false` при открытой панели — слушатели снимаются,
  родитель узнаёт о закрытии; стал `true` — состояние применяется заново
  после рендера;
- без Popover API и вне документа управлять нечем, исключений нет.

### 4.4. `closeOnClick`

Обработчик клика стоит на самой панели, как сейчас у меню: клик по любому
пункту или по отступу панели закрывает её, после обработчика пункта.
Метод `close()` вместо пропа потребовал бы от `PopoverMenu` своего
обёрточного элемента вокруг пунктов — разметка меню изменилась бы.

### 4.5. Будущая анимация

Классы, общие для всех панелей, есть только в `PopoverPanel`. Анимация
появления на Popover API (`transition` и `@starting-style` на панели)
добавляется правкой этого файла и сразу действует во всех выпадающих
частях.

## 5. `placePopover`: `align: "start"`

`placePopover(anchor, popover, { maxWidth = null, align = "end" })`.

- `"end"` — как сейчас: правый край по правому краю кнопки, не ближе 8 px
  к краю окна; `maxWidth` ограничен местом слева.
- `"start"` — сравнивается место справа от левого края кнопки и место
  слева от её правого края (оба — до отступа 8 px от края окна). Справа
  не меньше — левый край панели по левому краю кнопки, ширина ограничена
  местом справа; иначе — правый край по правому краю кнопки, ширина
  ограничена местом слева. `maxWidth`, если задан, ограничивает ширину
  ещё и им.
- Вертикаль и высота — без изменений для обоих значений.
- `left`, `right`, `top`, `bottom`, `maxHeight` и `maxWidth` ставятся
  всегда: панель открывается снова у другой кнопки или другой стороной,
  и старые значения не должны остаться.

## 6. Компоненты на `PopoverPanel`

### 6.1. `PopoverMenu`

`PopoverPanel` с видом меню: `panel-class="bb:w-56 bb:rounded-md
bb:shadow-lg bb:bg-white bb:ring-1 bb:ring-black/5"`, `panel-role="menu"`,
`align="end"`, `:max-width="224"`, `arrows`, `close-on-click`,
`:has-content="hasActions"`. `v-model` пробрасывается. Слот `trigger`
передаётся дальше вызывающему компоненту. Пункты, их вид, `isLink`,
`select`, переходы через `withNavigation` — в `PopoverMenu`, без
изменений. Разметка меню (DOM) не меняется.

### 6.2. `DropdownButton` и `SelectSingle`

- Кнопка поля — в слоте `trigger` `<popover-panel>`, с `id` и
  `popovertarget`; `@click.prevent` и `bb:z-20` уходят. `<popover-panel>`
  получает классы, которые держат прежнюю раскладку кнопки рядом
  с ластиком.
- `v-model` `isOpen` пробрасывается в `PopoverPanel`; ластик скрыт, пока
  список открыт, — как сейчас.
- `align="start"`, `arrows`, `findSelected` — проп `DropdownButton`
  от `SelectSingle` (`activeItemElement`).
- Вид списка: рамка, фон, скругление и тень —
  `panel-class="bb:bg-white bb:border bb:border-gray-200 bb:rounded-md
  bb:shadow-lg"`; раскладка и разделители —
  `bb:flex bb:flex-col bb:py-1 bb:divide-y bb:divide-gray-200
  bb:divide-dashed` на списке `SelectSingle` внутри панели; `bb:mt-1`
  уходит — зазор 4 px даёт `placePopover`.
- Возврат фокуса на кнопку после закрытия остаётся в `DropdownButton`.
- `SelectSingle` убирает свой `moveMenuFocus`, `stopArrows`,
  `stopMovingFocus` и наблюдатель `isOpen`: стрелки ведёт `PopoverPanel`,
  иначе каждое нажатие срабатывало бы дважды. Закрытие при пропавших
  пунктах (`hasItems`) остаётся.

### 6.3. `PickDay`

- Кнопка поля с полем ввода — в слоте `trigger`, с `id` и
  `popovertarget`; `@click` и `bb:z-20` уходят.
- Клик по полю открывает календарь: `<label>` с полем внутри кнопки
  получает `bb:pointer-events-none`, и клик в любой точке поля — по тексту
  даты, подсказке или пустому месту — достаётся кнопке, у которой
  `popovertarget` (раздел 2). Поле остаётся для показа даты и для Pikaday
  (`field`); мышью оно фокус больше не получает — сейчас его всё равно
  отключает открытие календаря.
- `align="start"`, без стрелок; `v-model` — нынешнее `popupIsOpen`.
- Вид календаря — `panel-class="bb:bg-white bb:border bb:border-gray-200
  bb:rounded-md bb:shadow-lg"`; контейнер Pikaday внутри панели держит
  раскладку `bb:flex`; `bb:mt-1` уходит.
- Выбор даты закрывает календарь через `popupIsOpen`; поле отключено и
  ластик скрыт, пока календарь открыт, — как сейчас.

### 6.4. Удаляются

`src/components/Popup.vue`, `src/components/Overlay.vue`,
`tests/Overlay.test.js`. Escape закрывает панель средствами браузера
(`popover="auto"`): это работает и с расширением Safari владельца —
проверено на меню `DropdownButtonWithAction`.

В `tests/utilityPrefix.test.js` исключение для `v-bind="$attrs"`
остаётся, а комментарий к нему перестаёт ссылаться на `Popup.vue`.
Исключение для `panelClass` — раздел 4.2.

## 8. Браузеры

Без Popover API (Safari до 17, Chrome до 114, Firefox до 125) панели
списка и календаря видны в потоке всегда — так же, как меню. README
«Требования» называет все компоненты на Popover API.

## 9. Тесты

vitest и happy-dom, Popover API — заглушка `tests/popoverStub.js`. Каждый
новый тест сначала запускается и падает.

- `tests/DropdownButtonWithAction.test.js` (59) и
  `tests/HamburgerMenu.test.js` (21) — без изменений; их список до и
  после переноса `PopoverMenu` на `PopoverPanel` совпадает.
- `tests/SelectSingle.test.js` — восемь нынешних тестов получают
  заглушку Popover API (без неё в happy-dom `popovertarget` список
  не откроет); проверки внутри не меняются. Новые:
  - список — панель `popover="auto"`, кнопка открывает и закрывает её;
  - выбор пункта закрывает список, фокус возвращается на кнопку;
  - клик вне, прокрутка страницы и изменение размера окна закрывают;
    прокрутка внутри списка — нет;
  - список встаёт левым краем по полю; у нижнего края окна — вверх,
    высота ограничена местом до края;
  - открытие второго `SelectSingle` закрывает первый, родитель первого
    узнаёт о закрытии, `id` у панелей свои;
  - закрытая панель скрыта: у неё нет утилит отображения.
- `tests/PickDay.test.js` и `SelectDateInterval`:
  - кнопка поля открывает календарь, выбор даты закрывает;
  - `<label>` с полем не принимает клики (`bb:pointer-events-none`):
    заглушка Popover API ищет кнопку через `closest('[popovertarget]')`
    и откроет календарь и по клику на поле, поэтому сам клик по полю
    проверяется в браузере (раздел 11), а тест закрепляет класс;
  - клик по смене месяца внутри календаря не закрывает;
  - Escape и клик вне закрывают;
  - поле отключено и ластик скрыт, пока календарь открыт;
  - открытие календаря «до» закрывает календарь «от».
- `tests/popover.test.js` — `placePopover` с `align: "start"`: левый край
  по кнопке; разворот к правому краю, когда слева места больше; `maxWidth`

## 13. Принятые риски

- Клик вне списка или календаря доходит до элемента под курсором: тот же
  клик закрывает панель и срабатывает по тому, что под ней.
- Прокрутка страницы закрывает открытый список: прочитать список,
  прокручивая страницу колесом, нельзя — только прокруткой внутри списка.
- Без Popover API список и календарь видны всегда (раздел 8).
- Клавиатура календаря Pikaday не включается (раздел 1).
