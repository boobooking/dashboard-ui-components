# SSR в пакете и PickDayNative

Дата: 2026-10-06

> **`PickDayNative` в выпуск 0.11.0 не вошёл.** Компонент, переход
> `SelectDateInterval` на него и функции `formatIsoDay` / `parseIsoDay` убраны
> после ручной проверки (2026-10-06): в Safari поле даты не переходит к
> следующей части после двух цифр — набор `15032026` подряд оставляет дату
> неполной, и значение не приходит, а ввод даты должен быть одинаковым во всех
> браузерах. В 0.11.0 — только SSR: `PageCard` читает историю после
> монтирования, `PickDay` загружает pikaday лениво, тесты серверного рендера и
> гидратации. Разделы о `PickDayNative` остаются как исследование встроенного
> поля даты.

## 1. Цель и рамки

Пакет внедряется во все проекты. Поддержку серверного рендеринга (SSR)
дешевле сделать сейчас, чем потом обновлять каждый проект. Ни один проект
SSR сейчас не использует (проверены payments, cashback, pms, belarus, russia,
health-days-backend), поэтому эта поддержка делается на будущее.

Цель выпуска `0.11.0`: пакет загружается и рендерится на сервере, а серверная
разметка гидратируется без расхождений. Попутно появляется выбор даты на
встроенном поле браузера, без зависимости от pikaday.

В рамках задачи:

- SSR: `PageCard` читает историю вкладки после монтирования, `PickDay`
  загружает pikaday лениво;
- тест, который рендерит на сервере и гидратирует каждый экспортируемый
  компонент;
- новый компонент `PickDayNative` — тот же API, что у `PickDay`, на
  `<input type="date">`;
- `SelectDateInterval` переходит на `PickDayNative`;
- функции `formatIsoDay` и `parseIsoDay` в `src/date.js`;
- тесты, playground, README, выпуск `0.11.0`;
- обновление cashback до `^0.11.0`.

Вне рамок:

- удаление `PickDay` и зависимости `pikaday`: `PickDay` остаётся в пакете с
  прежним API и видом;
- payments: фильтров дат там нет, а изменение `PageCard` без SSR не видно —
  версия пакета не меняется;
- включение SSR в каком-либо проекте;
- доступность ластика `Eraser` (доступное имя, обход Tab, фокус после его
  исчезновения). Недостаток общий для всех компонентов с ластиком и
  решается отдельной задачей для всех сразу.

## 2. Что показало исследование

**Пакет не загружается без `window`.** `PickDay` импортирует `pikaday` на
верхнем уровне модуля, а pikaday обращается к `window` при загрузке модуля. В
Node `import('@boobooking/dashboard-ui-components')` (собранный `dist`) падает
с `ReferenceError: window is not defined`. Серверная сборка любого проекта,
импортирующая пакет, падает целиком — даже на страницах без `PickDay`.

**Серверный рендер компонентов.** При подменённом pikaday все семнадцать
компонентов отрендерены через `renderToString`: упал только `PageCard` (читает
`window.history` в `data()`). Остальные обращаются к `window` и `document`
только в `mounted()` и обработчиках событий (`Overlay`, `PickDay`); `useId`
(`ConfirmationModal`, `DropdownButtonWithAction`) даёт одинаковые id на
сервере и при гидратации. `Teleport` в пакете нет.

**Встроенное поле даты** (`<input type="date">`), проверено в Chrome 151 с
языком браузера en-US:

- видимый формат задаёт язык браузера, атрибут `lang` на поле не влияет:
  поле с `lang="ru"` показывает `mm/dd/yyyy`, набранное `15032026` стало
  3 декабря 2026;
- плейсхолдера нет: пустое поле показывает маску (`mm/dd/yyyy`,
  `дд.мм.гггг`);
- пока набирается год, на каждую цифру приходят `input` и `change` с новым
  значением: `0002-12-03`, `0020-12-03`, `0202-12-03`, `2026-12-03`;
- `showPicker()` из обработчика клика открывает календарь браузера; пока он
  открыт, набранные цифры в поле не попадают. В календаре — выбор месяца,
  кнопки «Clear» и «Today», первый день недели по языку браузера;
- иконку календаря скрывает
  `::-webkit-calendar-picker-indicator { display: none }`.

**Встроенное поле в трёх движках**: Chrome 151 через DevTools MCP (язык
en-US), а также WebKit 26.6 и Firefox 155 в Playwright на macOS (headless,
язык en-GB). Наблюдения WebKit в Playwright — ещё не поведение Safari: Safari
проверяется вручную (§11).

- Клик по части даты выделяет её для ввода с клавиатуры. Календарь,
  открытый `showPicker()` из обработчика клика, забирает клавиши: в Chrome
  обычное поле после клика по месяцу и набора `03152026` получило
  `2026-03-15`, поле с `showPicker()` по клику не получило ни одного
  `keydown`.
- Иконка календаря есть у поля Chrome и Firefox. У поля WebKit в Playwright
  иконки нет, а пустое поле показывает серую сегодняшнюю дату.
- Firefox рисует иконку цветом текста (`currentColor`). Поэтому
  `color: transparent` скрывает её вместе с маской пустого поля. Свойство
  `-webkit-text-fill-color: transparent` скрывает текст маски, а иконку
  оставляет: проверено в Chrome, Firefox и WebKit.
- Автоматическую ширину поля браузер считает сам: ни псевдоэлементы, ни
  `field-sizing: content` её не меняют. Явная `width` применяется — так
  размер поля и задаётся, — но не гарантирует, что дата, иконка и ластик
  поместятся при любом языке браузера и шрифте. Замер для поля с геометрией
  компонента (`py-2 pr-3`, рамка 1 px), видимой иконкой и системным шрифтом
  16 px: Chrome — 164 px, из них около 40 px свободны между датой и иконкой;
  Firefox — 145 px у пустого поля и 140 px с датой: маска шире даты; WebKit
  — 111 px. В Chrome и WebKit ширина с датой и без неё одинакова. Ластик —
  32 px.
- Что Safari и Firefox делают по клику в поле без `showPicker()` —
  открывают ли календарь, принимают ли тогда клавиши — и что делает кнопка ●
  календаря Safari, автоматизация не показывает. В WebKit из Playwright
  клавиши после клика не доходят даже до обычного поля, а Firefox headless
  принимает их и при `showPicker()`. Это проверяется вручную (§11).

**Ряд фильтров cashback.** На всех пяти страницах §2 фильтры стоят в `flex`
без переноса, внутри `inline-block min-w-full`. Ряд не перестраивается:
более широкий интервал сдвигает соседние фильтры вправо и может расширить
страницу. Ширина страницы зависит и от таблицы, а при пустой выдаче таблицы
нет. Последствия измеряет приёмка (§11).

**cashback-vetkit-register.** Встроенное поле стояло в legacy-форме; при
переводе на Vue его заменили на `@vuepic/vue-datepicker` ради видимого
формата `ДД.ММ.ГГГГ` (спека `2026-07-14-birthdate-picker-design.md` того
проекта). Для дашборда видимый формат по языку браузера приемлем.

**Где используется выбор даты.** Напрямую `PickDay` в проектах не
используется. В cashback даты выбираются через `SelectDateInterval` на пяти
страницах: `Payments/Index`, `Messages/Index`, `Cashbacks/Index`,
`Consumers/Index`, `Services/Index`. В payments `SelectDateInterval` нет.

## 3. SSR

### 3.1. PageCard

`data()` возвращает `canGoBack: false`; `mounted()` выставляет
`canGoBack = window.history.length > 1`. Сервер и гидратация отдают карточку
без крестика и с `--bb-closer-space: 0px`; сразу после монтирования крестик
появляется, если в истории больше одной записи.

Без SSR перерисовка после монтирования происходит до первой отрисовки кадра и
не видна. Под SSR на экранах уже `md` заголовок один раз сдвигается, когда
крестик появляется: на сервере история вкладки неизвестна, и сервер рисует
состояние без нерабочей кнопки.

Комментарий в `data()` о чтении при создании переписывается: значение
читается один раз после монтирования.

### 3.2. PickDay

- Статический `import Pikaday from "pikaday"` заменяется загрузкой в
  `mounted()`: `const { default: Pikaday } = await import("pikaday")`.
  Импорт CSS (`pikaday/css/pikaday.css`) остаётся статическим: при сборке он
  попадает в `style.css`.
- Если компонент размонтирован до окончания загрузки, календарь не создаётся
  (флаг, выставляемый в `beforeUnmount`).
- `syncPicker` и `clearPicker` не падают, пока календаря ещё нет: значение
  поля задаёт Vue (`:value="dayValue"`), а pikaday при создании читает его из
  поля.
- `beforeUnmount` уничтожает календарь, если он создан (как сейчас).

Внешний вид и API `PickDay` не меняются.

### 3.3. Правило для компонентов

В README, раздел «Правила API пакета», — новое правило: компонент обращается
к `window`, `document` и другим API браузера только в `mounted()`,
`beforeUnmount()` и обработчиках событий; загрузка модуля и `data()`,
`computed`, рендер работают без браузера. Правило проверяет
`tests/ssr.test.js` (§7).

## 4. Компонент `PickDayNative`

    <pick-day-native v-model="date" placeholder-text="от" />

API совпадает с `PickDay`:

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `modelValue` | `String` | `""` | Дата `ДД.ММ.ГГГГ` или пустая строка |
| `withEraser` | `Boolean` | `true` | Показывать ли ластик очистки |
| `placeholderText` | `String` | `""` | Подпись пустого поля |
| `lang` | `String` | язык плагина | `"ru"` или `"en"`; ради одинакового API |

События: `update:modelValue` и `changed` — всегда парой, по правилу §4.4 и по
ластику.

### 4.1. Разметка и вид

- Корень — `bb-dashboard-ui bb:flex bb:flex-col bb:w-fit`: ширину компонента
  задаёт поле, а не родитель. Внутри — `bb:relative bb:flex bb:h-full
  bb:leading-none`: поле, подпись поверх него и ластик. Поле не
  заворачивается в `<button>` и `<label>`, как в `PickDay`: интерактивный
  элемент внутри кнопки недопустим, а клик обрабатывает само поле.
- Поле — `<input type="date">` с автоматической шириной, которую браузер
  считает по своему формату даты (§2); `w-full` нет. Автоматическая ширина
  выбрана, чтобы сохранить раскладку поля браузера: явная ширина не
  гарантирует, что дата, иконка и ластик поместятся при любом языке браузера
  и шрифте. Остальная геометрия — как у поля `PickDay`: `h-full py-2
  leading-none`, рамка 1px `border-transparent`, прозрачный фон,
  `whitespace-nowrap`, `focus:outline-hidden`; без левого отступа — его
  задаёт родитель. `cursor-pointer` нет ни у поля, ни у обёртки: клик по полю
  ставит ввод в часть даты, курсор над полем — браузерный.
- Правый отступ поля — место под ластик. При `withEraser` это `pr-8`
  (32 px, ширина ластика) и с датой, и без неё: появление ластика не меняет
  ширину компонента. Без ластика — `pr-3`. В Firefox ширину поля меняет и
  сам текст — маска пустого поля шире даты (§2), — поэтому там при выборе
  даты компонент становится уже на несколько пикселей.
- Иконка календаря браузера видна в любом состоянии поля. В Chrome и Firefox
  она стоит в конце поля, перед местом ластика, и ластик её не перекрывает.
  У поля WebKit в Playwright иконки нет (§2); про Safari скажет ручная
  проверка.
- Подпись: пока в поле нет даты (значение поля по §4.3 пустое) и оно не в
  фокусе, текст поля прозрачен, и маска браузера не видна; поверх поля, у
  левого края и по центру по вертикали, — `placeholderText` в стиле
  подсказки `PickDay`: `text-sm`, `text-gray-300`. Прозрачность задаёт
  `bb:[-webkit-text-fill-color:transparent]`, а не `bb:text-transparent`:
  иконку Firefox рисует цветом текста, и `color: transparent` скрыл бы её
  вместе с маской (§2). Подпись пропускает клики в поле
  (`pointer-events-none`). При пустом `placeholderText` подписи нет, а маска
  в пустом поле без фокуса всё равно скрыта — как пустое текстовое поле
  `PickDay` без подсказки; иконка при этом видна.
- В фокусе видна маска браузера; с датой — дата в формате браузера.
- Ластик — компонент `Eraser`, как в `PickDay`: `bb:z-10 bb:h-full bb:pr-2`.
  Он стоит в правом отступе поля.

### 4.2. Календарь

Компонент сам календарь не открывает: `showPicker()` не вызывается,
обработчика клика у поля нет. Клик по части даты выделяет её для ввода с
клавиатуры. Календарь открывается так, как это устроено в браузере: в Chrome
и Firefox — иконкой календаря, в Safari — так, как решает Safari (у поля
WebKit в Playwright иконки нет; поведение Safari фиксирует ручная проверка,
§11).

Открытие календаря по клику в любом месте поля отменено: такой календарь
забирал клавиши (§2), а выделенная при этом часть даты обещала ввод с
клавиатуры.

### 4.3. Значение поля

Поле показывает даты с годом 1000–9999 — дальше «диапазон дат». Значение
поля — `formatIsoDay(date)`, если `parseDay(modelValue)` разбирает дату и её
год в диапазоне дат, иначе пустая строка. `null` и `undefined` считаются
пустой строкой.

Нижняя граница — выбор компонента, а не требование HTML: HTML требует только
положительный год, а граница 1000 отсекает промежуточные годы при наборе
(§4.4).

Диапазон применяется и к значению от родителя, а не только к вводу:
`parseDay` разбирает, например, `"01.01.0000"`, а HTML принимает в поле даты
только положительный год и очищает недопустимое значение. Без диапазона поле
было бы пустым, а подпись скрыта и ластик виден. Подпись (§4.1) и ластик
(§4.5) смотрят на значение поля, поэтому всегда согласованы с ним.

Значение, изменённое родителем, поле показывает сразу и без событий:
ответный `update:modelValue` вернул бы родителю его же значение.

### 4.4. Когда значение уходит родителю

По событию `input` поля:

1. `validity.badInput` истинно (поле заполнено частично) — ничего не уходит;
2. значение поля пустое (без `badInput`): браузер сообщил, что поле очищено
   целиком одним действием, например кнопкой очистки календаря, — кандидат
   `""`;
3. иначе `parseIsoDay(value)`; если дата не разобрана или её год вне
   диапазона дат (§4.3) — ничего не уходит (так отсекаются промежуточные
   `0002`, `0020`, `0202` при наборе года); иначе кандидат `formatDay(date)`.

Кандидат уходит, только если отличается от текущего `modelValue` (`null` —
как `""`): `update:modelValue` с кандидатом и `changed`.

Полный ввод в пустое поле даёт одно событие. Пока заполнены не все части,
поле неполное (`badInput`), а промежуточные годы отсекает диапазон.

Каждое допустимое значение, которое сообщил браузер и которое отличается от
`modelValue`, даёт одно событие компонента. Сколько промежуточных значений
браузер сообщает при правке заполненной даты, зависит от браузера. Проверено
набором дня `15` в дате `20.03.2026`:

| Среда | Ввод | Значения |
| --- | --- | --- |
| Chrome 151, DevTools MCP | клик по дню | `01.03.2026`, затем `15.03.2026` |
| WebKit 26.6, Playwright | вход в день через Tab | `01.03.2026`, затем `15.03.2026` |
| Firefox 155, Playwright | вход в день через Tab | только `15.03.2026` |

Промежуточные события при правке — принятая цена правила.

Стирание частей даты с клавиатуры браузер сообщает одним событием — когда
стёрта первая часть, с `badInput`. Когда стёрта последняя часть, события нет:
проверено в Chrome 151, WebKit 26.6 и Firefox 155. Поэтому полная очистка с
клавиатуры фиксируется при потере фокуса.

**Потеря фокуса.** По `blur`:

- если у `modelValue` есть дата (значение поля по §4.3 непустое), а поле
  полностью пустое (`value` пустое, `badInput` ложно), дату стёрли целиком.
  Уходит кандидат `""` по правилу выше — `update:modelValue` с `""` и
  `changed`, — и поле, как и после остального ввода, показывает
  `modelValue`: при `v-model` оно пустое, а у родителя, который новое
  значение не принял, в поле снова его дата;
- иначе поле снова показывает значение по §4.3, то есть текущий
  `modelValue`, без событий. Незавершённый ввод — частичная дата или год вне
  диапазона дат — отбрасывается. Было `15.03.2026`, месяц стёрт, фокус ушёл
  — в поле снова `15.03.2026`, и фильтр по-прежнему использует эту дату. У
  изначально пустого поля частичный ввод стирается, видна подпись. Значение
  записывается в элемент напрямую: привязка Vue не перерисует поле, пока её
  собственное значение не изменилось.

Если `modelValue` не разбирается или год вне диапазона (значение поля по
§4.3 пустое), пустое поле при потере фокуса событий не даёт: значение
родителя компонент сам не меняет.

После размонтирования потеря фокуса ничего не отправляет. Chrome шлёт `blur`
и при удалении поля в фокусе, поэтому без этой проверки уход со страницы с
очищенным полем отправил бы родителю `""`. Признак размонтирования
выставляется в `beforeUnmount` — как в `PickDay`.

### 4.5. Ластик

Виден, если `withEraser` и в поле есть дата — значение поля (§4.3) непустое.
Клик: `update:modelValue` с `""` и `changed`. Значение `modelValue`, которое
`parseDay` не разбирает или чей год вне диапазона дат, поле показывает
пустым, с подписью и без ластика.

### 4.6. Язык и доступность

- Своих текстов у компонента нет: подпись приходит пропом, видимый формат,
  первый день недели и вид календаря задаёт браузер. `lang` подключается
  миксином `withLang` ради одинакового с `PickDay` API.
- `aria-label` поля — `placeholderText`, если он непустой; иначе атрибута нет.
- Подпись для скринридера — `aria-hidden="true"`: имя поля уже в
  `aria-label`.
- Ластик — общий компонент пакета `Eraser`, тот же, что у `PickDay`,
  `Search`, `SelectSingle` и `RussianMobileFilter`: он вне обхода Tab
  (`tabindex="-1"`) и без доступного имени. Это общий недостаток всех

**Ручная проверка в Safari и Firefox** — её выполняет владелец пакета, на
playground и на тестовой странице с обычным полем даты рядом:

- клик по части даты и набор даты с клавиатуры: компонент ведёт себя так
  же, как обычное поле этого браузера;
- календарь: Firefox — открывается иконкой, в том числе у изначально пустого
  поля; Safari — так же, как у обычного поля; выбор даты в календаре даёт одно
  событие;
- Safari, кнопка ● календаря: компонент ведёт себя так же, как обычное поле;
- Firefox: ластик не перекрывает иконку; в интервале дата видна целиком.

Расхождение с обычным полем браузера в кликах, вводе с клавиатуры и
календаре — дефект компонента; поведение самого браузера — запись в README.
Намеренные отличия от обычного поля этим сравнением не проверяются: диапазон
годов (§4.3), скрытая маска с подписью (§4.1), возврат значения при уходе
фокуса (§4.4).

Обязательны во всех трёх браузерах — Chrome, WebKit, Firefox — и не
заменяются записью в README:

- значение не теряется: после ввода, выбора и ухода из поля `modelValue` и
  поле согласованы по §4.3–4.4;
- частичная дата и год вне диапазона дат не уходят родителю;
- лишних событий нет: полный ввод в пустое поле — одно событие с
  `ДД.ММ.ГГГГ`; правка заполненной даты — одно событие на каждое
  отличающееся допустимое значение, которое сообщил браузер, и не больше.
  Ожидаемые последовательности задаёт таблица §4.4 для проверенной среды и
  способа ввода. Частичный ввод и уход из поля — ни одного события;
- ластик очищает одним событием; стирание всех частей с клавиатуры и уход
  из поля — одно событие с пустой строкой;
- маска пустого поля без фокуса скрыта, подпись не накладывается на текст;
- иконка календаря видна в любом состоянии поля там, где браузер её рисует;
- ластик не перекрывает иконку календаря; дата в половинах интервала видна
  целиком.

Невыполнение любого из этих пунктов — дефект компонента: приёмка не пройдена,
пока он не исправлен. Записью в README допускаются только отличия вида и
поведения самого браузера: вид календаря и как он открывается, видимый
формат даты, первый день недели, наличие иконки календаря у поля браузера,
ширина поля, которую задаёт браузер.
