# DropdownButtonWithAction: пункты меню данными

Дата: 2026-10-07

## 1. Цель и рамки

Пункты меню `DropdownButtonWithAction` сейчас — разметка проекта в слоте
`actions`: проект сам выбирает элементы и классы, и вид меню живёт
в каждом проекте отдельно. Это всплыло на навигации по меню стрелками
(ветка `fix/keyboard-navigation`): подсветка пункта — это фокус, а у пунктов
проектов есть только `hover:`, и пункт под стрелкой в Safari почти не виден.
Чинить это пришлось бы в каждом проекте.

Цель: вид пунктов меню целиком принадлежит библиотеке — обычный пункт,
подсветка при фокусе и наведении, опасный пункт. Проект только говорит,
какие пункты есть и что они делают; передать свою разметку или классы
пунктов он не может. Любое изменение вида делается в пакете и приходит
в проекты обновлением версии.

В рамках задачи (выпуск пакета `0.14.0`):

- проп `actions` у `DropdownButtonWithAction` вместо слота `actions`;
- разметка, вид и поведение пунктов в самом компоненте;
- предупреждение в режиме разработки, если проект ещё передаёт слот;
- тесты, playground, README с разделом «Обновление с 0.13»;
- выпуск `0.14.0` вместе с уже сделанной на ветке клавиатурой.

Вне рамок:

- перевод четырёх меню в проектах — свои задачи в их репозиториях
  (раздел 9 даёт образец замены);
- основная кнопка (слот `button`) — не меняется;
- версия `1.0.0` на npm (раздел 11) — не трогаем.

## 2. Что показало исследование

**Меню в проектах.** Четыре меню в трёх проектах, пункты двух видов:

| Проект | Страница | Пункты |
| --- | --- | --- |
| certificates | `Users/Index.vue` | «Поменять пароль» (переход), «Удалить» (действие, красный) |
| cashback | `Users/Index.vue` | «Поменять пароль» (переход), «Удалить» (действие, красный) |
| payments | `Users/Index.vue` | «Change password» (переход), «Delete» (действие, красный) |
| payments | `PaymentAgents/Index.vue` | «Delete» (действие, красный) |

Переход — Inertia `<Link :href="route(…)">` с классами
`block px-4 py-2 text-sm text-gray-700 hover:bg-gray-100 hover:text-gray-900`.
Действие — `<a href="#" @click.prevent="…" role="menuitem">` с классами
`block px-4 py-2 text-sm bg-red-400 hover:bg-red-500 text-white`. Классы
скопированы между проектами без изменений. На страницах групп certificates
`DropdownButtonWithAction` используется без пунктов — только слот `button`.

**Подсветка с клавиатуры.** Проверено в Safari владельцем: стрелки по меню
работают (страница не прокручивается, Enter нажимает пункт), но пункт
под фокусом не выделен — у ссылки только стандартная рамка браузера.

**Что уже есть в пакете.** `withNavigation` (`src/navigation.js`) — ссылка
пакета: обычный клик уходит в `navigate(href)` плагина `dashboardUi`, клик
с модификаторами и средней кнопкой остаётся браузеру; без `navigate` —
обычная ссылка. `Pagination` уже подключает `withLang` и `withNavigation`
вместе. `moveMenuFocus` (`src/menuFocus.js`) ведёт фокус по `a[href]`
и `button` меню стрелками и мышью. Предупреждения пакет выводит
валидаторами пропов (`DataTable`, `withLang`).

| Пункты передаются данными (проп), а не разметкой или компонентом пункта | владелец, вариант A из трёх |

## 4. Проп `actions`

### 4.1. Пример

Меню страницы администраторов после перевода:

```vue
<dropdown-button-with-action
    :actions="[
        { label: 'Поменять пароль', href: route('user.password.edit', { user: row.getId() }) },
        { label: 'Удалить', danger: true, onSelect: () => prepareUserDelete(row) },
    ]"
>
    <template #button>…</template>
</dropdown-button-with-action>
```

### 4.2. Пункт

| Поле | Тип | Смысл |
| --- | --- | --- |
| `label` | `String`, обязательно, непустой | Текст пункта |
| `href` | `String`, непустой | Пункт-переход |
| `onSelect` | `Function` | Пункт-действие: вызывается при выборе без аргументов |
| `danger` | `Boolean`, по умолчанию `false` | Опасный пункт, красный |

У пункта ровно одно из `href` и `onSelect`. `danger` допустим у пунктов
обоих видов. Другие поля пункта компонент не читает и не проверяет.

Проп: `type: Array`, `default: () => []`. `null` и `undefined` — пустой
список (правило пакета: компоненты не падают на `null`); Vue не вызывает
валидатор для `null` у необязательного пропа.

### 4.3. Валидатор

Валидатор пропа проверяет весь список: каждый элемент — объект (не `null`),
`label` — непустая строка, ровно одно из «`href` — непустая строка»
и «`onSelect` — функция», `danger` — `undefined` или логическое. Неверный
список даёт стандартное предупреждение Vue о пропе в режиме разработки;
компонент при этом не падает. Элемент выбирается по `href`: непустая
строка — ссылка (`onSelect` у такого пункта не вызывается), иначе — кнопка.
Пункт, у которого нет ни `href`, ни `onSelect`, рисуется кнопкой без
действия, а клик по нему только закрывает меню.

### 4.4. Без пунктов

Пустой список (или `null`) — стрелки нет, и основная кнопка скругляется
с обеих сторон. Сейчас это решает наличие слота `actions`, теперь — длина
списка. Меню (`[popover]`) без пунктов не рендерится, как и сейчас без слота.

### 4.5. Убранный слот

Слот `actions` компонент больше не рисует. Если проект его передаёт, в
`created` компонент пишет в консоль `console.warn`:

```
[dashboard-ui-components] DropdownButtonWithAction: слот actions убран, пункты меню передаются пропом actions
```

Только в режиме разработки: проверка `process.env.NODE_ENV !== "production"`,
как в самом Vue. В библиотечной сборке Vite `process.env.*` не подменяет,
и проверку подменяет бандлер проекта: в продакшен-сборке она и
предупреждение вырезаются.

## 5. Разметка и поведение

### 5.1. Переход

`<a :href="item.href" role="menuitem" @click="followLink($event, item.href)">`
через `withNavigation`. Компонент подключает `mixins: [withLang, withNavigation]`,
как `Pagination`.

### 5.2. Действие

`<button type="button" role="menuitem" @click="item.onSelect?.()">`. Кнопка
ничего не открывает и не меняет адрес на `#`, в отличие от нынешнего
`<a href="#" @click.prevent>` в проектах.

### 5.3. Закрытие

Как и сейчас, клик по любому пункту закрывает меню: обработчик
`@click="close"` на самом меню не меняется. Клик по пункту доходит до меню
всплытием, поэтому `onSelect` (или `followLink`) срабатывает раньше
закрытия: модалка подтверждения, которую открывает `onSelect`, не окажется
под открытым меню. `update:modelValue(false)` — как и сейчас.

### 5.4. Вид

Повторяет нынешние классы проектов, чтобы после перевода ничего внешне
не поменялось:

| | Обычно | Подсветка (фокус) |
| --- | --- | --- |
| Обычный пункт | `bb:text-gray-700` | `bb:focus:bg-gray-100 bb:focus:text-gray-900` |
| `danger` | `bb:bg-red-400 bb:text-white` | `bb:focus:bg-red-500` |

Общие классы пунктов: `bb:block bb:w-full bb:px-4 bb:py-2 bb:text-sm
bb:text-left bb:cursor-pointer bb:focus:outline-hidden`. `bb:w-full`
и `bb:text-left` — чтобы кнопка выглядела как ссылка. Стилей `hover:` нет:
подсветка — это фокус, и мышь ставит его через `moveMenuFocus`, как
у `ListElement` в `SelectSingle`. Подсвечен всегда один пункт — тот,
на который последними указали клавиатура или мышь; после ухода мыши
с меню он остаётся подсвеченным.

Углы: у `[popover]` в стилях браузера `overflow: auto`, содержимое
обрезается по скруглению меню, и красный нижний пункт за скругление
не выходит. Проверяется в браузере (раздел 10).

### 5.5. Клавиатура и мышь

Без изменений: `moveMenuFocus` ходит по `a[href]` и `button` меню, а пункты
— ровно такие элементы.

### 5.6. SSR

Пункты рендерятся на сервере той же разметкой; `onSelect` в разметку
не попадает. `tests/ssrFixtures.js` переходит на проп, гидратация без
расхождений — как у остальных компонентов.

## 6. Тесты

По TDD: сначала падающий тест, потом код. В `tests/DropdownButtonWithAction.test.js`:

- `href` рисуется `<a>` с этим `href`, `onSelect` — `<button type="button">`;
  у обоих `role="menuitem"` и текст `label`;
- клик по пункту-действию вызывает `onSelect` ровно один раз и закрывает меню
  (`update:modelValue` — `[[true], [false]]`);
- клик по пункту-переходу при плагине с `navigate` вызывает `navigate(href)`,
  клик с `metaKey` — не вызывает (правила `shouldNavigateInApp` покрыты
  в `tests/navigation.test.js`, здесь — подключение);
- `actions: []` и `actions: null` — стрелки нет и предупреждений нет;
- валидатор: таблица неверных списков (элемент `null`, нет `label`, пустой
  `label`, оба `href` и `onSelect`, ни одного, пустой `href`, `danger` —
  строка) — предупреждение Vue через `global.config.warnHandler`; верный
  список — без предупреждений;
- переданный слот `actions` не рисуется, `console.warn` вызван ровно один
  раз с текстом из раздела 4.5 (перехвачен шпионом — вывод тестов чистый).

Существующие тесты `DropdownButtonWithAction` (открытие, закрытие, v-model,
стрелки), `tests/i18n.test.js` и `tests/ssrFixtures.js` переходят со слота
на проп. Вид (красный пункт, подсветка, углы) — в браузере, а не юнит-тестом:
тест на строку классов ловил бы только переименования.

## 9. Перевод проектов

Каждый проект при обновлении до `0.14.0`: `npm install
@boobooking/dashboard-ui-components@^0.14.0` (для `0.x` знак `^` пропускает
только патчи, поэтому `^0.13.0` версию `0.14.0` не возьмёт) и замена слота
на проп. Было (certificates, `Users/Index.vue`):

```vue
<template v-slot:actions>
    <Link
        class="block px-4 py-2 text-sm text-gray-700 hover:bg-gray-100 hover:text-gray-900"
        :href="route('user.password.edit', {'user': row.getId()})"
    >
        Поменять пароль
    </Link>
    <a
        href="#"
        @click.prevent="prepareUserDelete(row)"
        class="block px-4 py-2 text-sm bg-red-400 hover:bg-red-500 text-white"
        role="menuitem"
    >
        Удалить
    </a>
</template>
```

Стало:

```vue
<dropdown-button-with-action
    :actions="[
        { label: 'Поменять пароль', href: route('user.password.edit', { user: row.getId() }) },
        { label: 'Удалить', danger: true, onSelect: () => prepareUserDelete(row) },
    ]"
>
```

Так же — cashback `Users/Index.vue`, payments `Users/Index.vue`
и `PaymentAgents/Index.vue` (один пункт `{ label: 'Delete', danger: true,
onSelect: () => prepareAgentDelete(agent) }`). Переход через `href`
работает через `navigate` плагина: во всех трёх проектах он подключён
к `router.visit`.

- Весь набор тестов зелёный, вывод без предупреждений и ошибок; сборка
  пакета проходит.

## 11. Принятые риски

- Проект, обновивший пакет без перевода меню, получает кнопку без стрелки:
  в продакшене — молча, в режиме разработки — с предупреждением в консоли.
  Перевод меню — часть обновления, он описан в README.
- Предупреждение о слоте опирается на `process.env.NODE_ENV`, который
  подменяет бандлер проекта. Тот же механизм нужен самому Vue
  (`vue.runtime.esm-bundler`), так что в работающем проекте он уже есть.
- После ухода мыши с меню последний пункт под курсором остаётся
  подсвеченным: подсветка — это фокус.
- На npm опубликована версия `1.0.0` от 2026-09-13 — в ту же секунду,
  что и создание пакета; тег `latest` на ней нет. `^1.0.0` и `@1` ставят
  её. Номер не занять заново; `npm deprecate` — решение владельца.
