# ConfirmationModal: галочка согласия и слот текста

Дата: 2026-11-24

## 1. Цель и рамки

Дашборд vetkit переезжает на пакет. Перед скачиванием отчёта с персональными
данными он показывает модалку «Выгрузка персональных данных». В ней текст с
абзацем и списком обязательств, где часть фраз выделена жирным, и галочка
«Подтверждаю». Пока галочка не поставлена, кнопка «Скачать» выключена.
У `ConfirmationModal` пакета нет ни галочки, ни способа показать
форматированный текст.

В рамках задачи:

- проп `agreementText` у `ConfirmationModal`: галочка согласия, без которой
  действие недоступно;
- слот по умолчанию у `ConfirmationModal` — тело модалки вместо
  `confirmationText`;
- круг фокуса модалок пакета включает галочку согласия;
- тесты, Playground, README.

Вне рамок:

- перевод vetkit на пакет — отдельная задача после выпуска;
- выпуск: версия 0.27.0, тег и публикация — по слову владельца.

## 2. Что показало исследование

- `src/components/ConfirmationModal.vue`: тело — `<div class="bb:mt-2"><p
  class="bb:text-sm bb:text-gray-500">{{ confirmationText }}</p></div>`.
  Кнопка действия — `ActionButton` без `isDisabled`. Модалка смонтирована
  всегда, видимость задаёт `isOpen`. Слотов нет.
- `ActionButton` принимает `isDisabled`: кнопка погашена и не кликается.
- `src/dialogFocus.js`: `ITEMS = 'a[href], button:not(:disabled)'`. Tab
  ходит по кругу только по кнопкам и ссылкам, и чекбокс в этот круг не попал
  бы. Первым фокус получает элемент с `data-dialog-focus`, то есть кнопка
  отмены.
- Чекбокс пакета уже есть в `SelectMultipleList.vue`: `input` с классами
  `bb:size-4 bb:rounded bb:choice-border bb:bg-none
  bb:focus-visible:focus-ring bb:forced-colors:appearance-auto`, цвет по
  состоянию и SVG-галочка поверх.
- В vetkit (`Shared/ConfirmationModalWithCheckbox.vue`) текст выводится через
  `v-html`, состояние галочки внутреннее (`user_confirmation`), подпись по
  умолчанию — «Подтверждаю». Модалка монтируется через `v-if`, поэтому при
  каждом открытии галочка снята.
- Стили пакета не ресетят `ul`, `li`, `b`. В приложении действует его
  собственный preflight, и классы приложения внутри слота работают как на
  странице.

## 3. Подходы

| Подход | Итог |
| --- | --- |
| Проп у `ConfirmationModal` | выбран владельцем: отличие — одна строка с галочкой и выключенная кнопка; без пропа модалка прежняя |
| Отдельный `ConfirmationWithAgreeModal` | отброшен: повторил бы `ConfirmationModal` почти целиком (иконка, заголовок, кнопки, фокус, Escape), две модалки расходились бы |
| Форматированный текст: слот тела | выбран владельцем: текст и выделения остаются как есть, `v-html` уходит; вид содержимого слота задаёт страница |
| Форматированный текст: проп-массив пунктов | отброшен: жирные фразы внутри пунктов пропали бы |
| Форматированный текст: один абзац | отброшен: теряются список и выделения |

## 4. Решения и их источники

| Решение | Источник |
| --- | --- |
| Галочка — проп у `ConfirmationModal`, не отдельный компонент | владелец |
| Форматированный текст — слот | владелец |
| Имя пропа — `agreementText` (`String`, по умолчанию `null`); галочка есть, когда строка непустая | автор |
| Состояние галочки внутреннее, наружу не отдаётся; при каждом открытии (`isOpen` → `true`) она снята | автор: странице нужна только блокировка действия, `v-model` галочки никому не нужен |
| Слот по умолчанию заменяет абзац `confirmationText`; обёртка слота — `bb:mt-2 bb:text-sm bb:text-gray-500`, как у абзаца | автор |
| В круг фокуса добавляется только галочка пакета по маркеру: `input[data-dialog-agreement]:not(:disabled)`. Произвольные поля слота не входят: недоступное поле (скрытое, `inert`) в круге зациклило бы Tab | автор, по ревью Codex (SPEC-001) |
| Разметка чекбокса — как в `SelectMultipleList` | автор |
| Версия 0.27.0 — минорная: новое, совместимое | автор |
| Работа в `main` | автор, как вся история пакета |

## 5. Поведение

**Слот.** Если слот по умолчанию передан, на месте абзаца `confirmationText`
стоит его содержимое в обёртке `<div class="bb:mt-2 bb:text-sm
bb:text-gray-500">`. `confirmationText` в этом случае не выводится. Без слота
всё как сейчас.

**Галочка** (`agreementText` — непустая строка):

- стоит под текстом (под слотом или абзацем), с отступом `bb:mt-4`. Это
  `<label>` с чекбоксом и подписью `agreementText` (`bb:text-sm
  bb:text-gray-900`). Клик по подписи переключает галочку;
- у чекбокса атрибут `data-dialog-agreement`;
- пока галочка снята, кнопка действия `isDisabled`. Условие блокировки
  булево: `Boolean(agreementText) && !agreed`, иначе пустая строка дошла бы
  до `isDisabled` и Vue превратил бы её в `true`. Клик по ней ничего не
  даёт, `actionConfirmed` не эмитится;
- когда галочка стоит, кнопка включена и работает как сейчас;
- при каждом переходе `isOpen` в `true` галочка снимается. Модалка,
  смонтированная сразу открытой, начинает со снятой;
- отмена, Escape и начальный фокус на кнопке отмены не меняются.

Без `agreementText` (`null` или `""`) галочки нет, кнопка действия включена,
как сейчас.

**Фокус.** `ITEMS` в `dialogFocus.js` — `'a[href], button:not(:disabled),
input[data-dialog-agreement]:not(:disabled)'`. Tab из отмены идёт на
галочку, затем на кнопку действия, если она включена. Пока галочка снята,
кнопка выключена и в круг не входит. Поля, которые страница положит в слот,
в круг не входят. Остальных модалок пакета это не касается: галочки в них
нет.

## 6. Тесты

**`tests/ConfirmationModal.test.js`:**

- без `agreementText` и с `agreementText: ""` — чекбокса нет, кнопка действия
  включена, клик эмитит `actionConfirmed` (существующие тесты не меняются);
- с `agreementText` — `label` с текстом пропа и чекбокс, не отмеченный;
  кнопка действия выключена, клик по ней не эмитит `actionConfirmed`;
  после отметки кнопка включена, клик эмитит одно `actionConfirmed`, без
  предупреждений Vue;
- отмеченная галочка, закрыть (`isOpen: false`) и открыть снова — галочка
  снята, кнопка выключена;
- смонтирована открытой с `agreementText` — галочка снята;
- слот по умолчанию — его разметка в теле в обёртке с классами из раздела 5,
  абзаца с `confirmationText` нет; без слота абзац на месте;
- фокус: открыта с `agreementText`, фокус на отмене; Tab — на чекбоксе; Tab —
  снова на отмене, пока кнопка выключена; после отметки Tab с чекбокса идёт на
  кнопку действия;
- в слоте перед галочкой недоступное поле (`input` внутри `inert`-блока) —
  Tab с отмены всё равно идёт на галочку.

**`tests/dialogFocus.test.js`:** `input[data-dialog-agreement]` внутри панели
входит в круг, тот же `input` с `disabled` — нет, `input` без маркера — нет.

**SSR и гидратация:** общая фикстура `ConfirmationModal` в
`tests/ssrFixtures.js` получает `agreementText` и слот по умолчанию — функцию,
возвращающую абзац и список. `tests/ssr.test.js` и
`tests/hydration.test.js` берут её как есть.
