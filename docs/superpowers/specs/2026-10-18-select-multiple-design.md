# SelectMultiple — фильтр с выбором нескольких пунктов

Дата: 2026-10-18

## 1. Цель и рамки

Фильтр «выбрать несколько пунктов из списка» — бренды, подразделения,
мероприятия, пользователи — в russia собран четыре раза почти одинаковыми
компонентами (раздел 2). В пакете есть `SelectSingle` — тот же фильтр
с одним выбранным пунктом, доведённый до стандарта пакета: клавиатура,
список в верхнем слое браузера, возврат фокуса, SSR, языки.

Цель: компонент пакета `SelectMultiple` — по смыслу тот же `SelectSingle`,
но выбрать можно несколько пунктов. Всё, что сделано в `SelectSingle`,
переходит в него. Поиск по списку включается пропом и по умолчанию
выключен. Компонент универсальный: все четыре компонента russia
переходят на него без доработок компонента.

В рамках задачи:

- публичный компонент `SelectMultiple`;
- правки внутренних частей пакета, которые ему нужны (раздел 18);
- тесты, Playground, README;
- выпуск `0.19.0` (раздел 15).

Вне рамок:

- перевод russia на `SelectMultiple` — отдельная задача: russia пока
  не подключает пакет вообще (Tailwind 3, свои копии компонентов);
  раздел 14 показывает, как пройдёт перевод, и подтверждает, что
  компоненту хватает API;
- своя формулировка счётчика для каждого фильтра («Выбрано брендов: 3»)
  и свои тексты поиска («Поиск мероприятий...»): тексты общие, из
  словаря пакета;
- «выбрать всё», группы пунктов, поиск на сервере, подгрузка пунктов;
- изменения поведения `SelectSingle`;
- подсказки Vimlike внутри открытой панели — известная отложенная
  задача (README, «Клавиатурная навигация»).

## 2. Что показало исследование

### 2.1. Четыре копии в russia

`~/Code/mars/russia/resources/js/Shared/`:

| Компонент | Страницы | Пункты | Поиск |
| --- | --- | --- | --- |
| `SelectMultipleBrand` | Archive, Consumers, Events, Sms | константа в компоненте: Royal Canin (`rc`), Eukanuba (`eukanuba`) | нет |
| `SelectMultipleGroup` | Archive, Users, Consumers, Events | проп `groups` — объекты `Group` | нет |
| `SelectMultipleEvent` | Consumers | проп `events` — объекты `Event` | да |
| `SelectMultipleUser` | Activity | проп `users` — объекты `User` | да |

Общее у всех четырёх:

- разметка — свои копии `ElementHeader`, `DropdownButton`, `ListElement`;
  пропы `header` и `isRequired`;
- значение — массив `id` в именованной модели
  (`v-model:selected-brands`, `v-model:selected-groups-ids`,
  `v-model:selected-events-ids`, `v-model:selected-users-ids`);
  объекты приводятся к `DictionaryElement` (`getName()`, `getObjectId()`,
  у бренда — `getApiKey()`);
- клик по пункту переключает его `id` в массиве (`xor` из lodash),
  эмитит новый массив и `changed`; **клик закрывает список**;
- ластик эмитит `[]` и `changed`;
- надпись на кнопке: ничего не выбрано — пусто; один — его имя;
  несколько — «Выбрано брендов: N» (подразделений, мероприятий,
  пользователей); считаются только `id`, найденные среди пунктов;
- без пунктов кнопки нет (`v-if="hasElements"`), заголовок остаётся;
  у брендов пункты есть всегда.

Поиск у мероприятий и пользователей — `LocalFilterInput` вверху
списка: поле в рамке с подсказкой «Поиск мероприятий...» /
«Поиск пользователей...», крестик очистки в поле; фильтр — имя содержит
запрос без учёта регистра, запрос обрезан по краям; без совпадений —
строка «Мероприятий не найдено» / «Пользователей не найдено». Клик по
пункту сбрасывает запрос.

Страницы на `changed` перезапрашивают выдачу
`router.get(route(...), query, { preserveState: true })`: компонент
переживает перезапрос, пункты приходят новым массивом.

### 2.2. `SelectSingle` в пакете

`src/components/SelectSingle.vue` на внутренних `ElementHeader`,
`DropdownButton` (кнопка, ластик, `PopoverPanel`) и `ListElement`.
Что в нём сделано и переходит в `SelectMultiple`:

- пункты `{ id, name }`, сравнение по `id`, а не по ссылке: список
  приходит новым массивом после каждого обновления пропсов;
- `v-model` вместо именованной модели (правило пакета);
- `null` и `undefined` в `items` — пустой список, без падения;
- список — `PopoverPanel` на Popover API: верхний слой, место у поля
  с разворотом у краёв окна, высота до края окна и прокрутка внутри,
  закрытие кликом вне (клик доходит до элемента), Escape, кнопкой,
  прокруткой страницы и изменением окна, открытием другой панели;
- стрелки и мышь ведут фокус по пунктам (`src/menuFocus.js`), отсчёт от
  выбранного; Enter и пробел выбирают; после закрытия фокус
  возвращается на кнопку (`returnFocus`);
- пункты пропали при открытом списке — список закрывается и вернётся
  закрытым;
- содержимое кнопок не ловит указатель и без курсора-руки: одна
  подсказка Vimlike на всю кнопку;
- ластик — `CrossButton` с анимацией нажатия;
- утилиты с префиксом `bb:`, SSR и гидратация без расхождений.

## 4. API `SelectMultiple`

    <select-multiple
        header="Бренд"
        :items="[{ id: 'rc', name: 'Royal Canin' }, { id: 'eukanuba', name: 'Eukanuba' }]"
        v-model="brands"
        @changed="reload"
    />

    <select-multiple header="Мероприятие" :items="events" v-model="eventIds" with-search @changed="reload"/>

### 4.1. Пропы и события

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `items` | `Array` | обязателен | Массив `{ id, name }` |
| `modelValue` | `Array` | `[]` | `id` выбранных пунктов |
| `header` | `String` | обязателен | Подпись поля |
| `isRequired` | `Boolean` | `false` | Пометка обязательности в заголовке |
| `isLoading` | `Boolean` | `false` | Индикатор загрузки в заголовке |
| `withSearch` | `Boolean` | `false` | Поле поиска вверху списка |
| `lang` | `String` | `null` | Язык текстов (миксин `withLang`) |

События: `update:modelValue` — новый массив `id`; `changed` — после
каждого изменения выбора кликом по пункту или ластиком.

- `id` — строка или число; сравнение строгое (`===`), как
  в `SelectSingle`.
- `null` и `undefined` в `items` — пустой список; в `modelValue` —
  ничего не выбрано. Компонент не падает; для обязательных пропов Vue
  предупреждает о типе (правило пакета).

### 4.2. Значение

- Клик по невыбранному пункту — его `id` добавляется в конец массива;
  по выбранному — убирается (все вхождения). Массив из пропа
  не меняется: эмитится новый. Затем — `changed`. Это поведение `xor`
  в russia.
- `changed` уходит после каждого клика, а не при закрытии списка: так
  ведут себя `SelectSingle` и копии russia, и страница сразу
  перезапрашивает выдачу. Со `preserveState: true` компонент
  переживает перезапрос. Открытый список переживает его, только если
  страница не прокручивается: без `preserveScroll` Inertia после
  ответа прокручивает окно наверх (`window.scrollTo(0, 0)`
  в `@inertiajs/core` 1.3.0 russia), и прокрутка закрывает список, как
  любую панель пакета. Поэтому страницы с `SelectMultiple`
  перезапрашивают выдачу с `{ preserveState: true, preserveScroll: true }`
  — так написано в README. Отличить свою прокрутку от прокрутки
  человека панель не может, и общий код панелей ради этого
  не меняется.
- `id` из `modelValue`, которых нет среди пунктов, при переключении
  других пунктов остаются в массиве, в надписи не считаются и ластик
  сами не показывают. Ластик эмитит `[]` — уходят и они.
- Порядок `id` компонент не меняет и не сортирует.

### 4.3. Надпись на кнопке

Считаются выбранные пункты среди всех `items` (не только видимых
в поиске):

- ни одного — надпись пустая, как у `SelectSingle` без выбора;
- один — его `name`;
- два и больше — «Выбрано: 3» / «Selected: 3» из словаря пакета.

Ластик виден, когда выбран хотя бы один пункт и список закрыт — как
у `SelectSingle`.

## 5. Список

Всё, как у `SelectSingle` (README, раздел `SelectSingle`, и 2.2):
открытие кнопкой, место, высота, прокрутка, все способы закрытия,
закрытие при пропаже пунктов, возврат фокуса на кнопку, одна открытая
панель на странице. Отличия:

- клик по пункту список **не закрывает**: следующий пункт выбирают
  сразу; фокус остаётся на пункте;
- галочка — у каждого выбранного пункта;
- пункт сообщает скринридеру, выбран ли он (`aria-pressed`): атрибут
  ставит `SelectMultiple`, Vue переносит его на корневую кнопку
  `ListElement`, сам `ListElement` не меняется; у пунктов `SelectSingle`
  разметка прежняя;
- без пунктов кнопки нет, заголовок остаётся — как у `SelectSingle`.

## 6. Поиск

`withSearch` выключен — поля нет, остальное как в разделах 4–5.

`withSearch` включён:

- поле — вверху списка, над пунктами; при прокрутке длинного списка
  оно остаётся на месте, прокручиваются пункты;
- пока список открыт, поле не двигается, сколько бы пунктов ни убрал
  фильтр. Панель не становится уже, чем при открытии. Открытая вниз —
  верх прижат под кнопкой — становится ниже вместе с найденным, поле
  при этом на месте. Открытая вверх — низ прижат к кнопке — не
  становится ниже, чем при открытии: пункты идут сразу под полем,
  пустое место остаётся под ними, у кнопки. При следующем открытии
  размер считается заново;
- подсказка в поле — «Поиск» / «Search»; она же — доступное имя поля
  (подсказка именем не считается);
- фильтр: имя пункта содержит запрос без учёта регистра, запрос
  обрезан по краям; пустой запрос или одни пробелы — все пункты;
- совпадений нет при непустом запросе — вместо пунктов строка «Ничего
  не найдено» / «Nothing found»;
- в поле — ластик, пока запрос не пуст: очищает запрос, фокус остаётся
  в поле;
- запрос — внутреннее состояние компонента, не часть `v-model`.
  Сбрасывается при каждом закрытии списка, по любой причине; клик по
  пункту его не сбрасывает;
- выбранные пункты, скрытые фильтром, остаются выбранными
  и считаются в надписи;
- при открытии списка — кнопкой мышью, Enter или пробелом на кнопке,
  расширением навигации — фокус встаёт в поле. При загрузке страницы
  фокус в поле не уходит. Без Popover API (список виден всегда) фокус
  в поле сам не ставится;
- пробел в поле печатает пробел и ничего не выбирает; Enter в поле
  ничего не делает и не отправляет форму, внутри которой стоит фильтр;
  Escape закрывает список. Поле — `type="text"`: у `type="search"`
  Escape в Chrome сначала стирает запрос и даёт свой крестик.

## 7. Клавиатура и мышь

Как у `SelectSingle`, пока список открыт:

- стрелки вверх и вниз ведут фокус по пунктам по кругу и страницу
  не прокручивают; у закрытого списка стрелки прокручивают страницу;
- Enter или пробел на пункте переключают его так же, как клик; список
  остаётся открытым, фокус — на пункте;
- Escape закрывает список, фокус возвращается на кнопку;
- движение мыши по пункту ставит фокус на него, подсвечен всегда один
  пункт.

Отсчёт, пока фокус вне пунктов и вне поля (на кнопке, на body):
от выбранного пункта, как у `SelectSingle`; если выбрано несколько —
от первого выбранного в порядке списка среди видимых; без выбранных —
вниз первый пункт, вверх последний.

С поиском поле — первая остановка круга: из поля вниз — первый пункт,
вверх — последний; с первого пункта вверх — в поле, с последнего
вниз — в поле. Ластик поля в круг не входит. Без совпадений стрелки
в поле ничего не делают.

С поиском набор текста, пока фокус на пункте, уходит в поле: печатный
символ (одна клавиша без Ctrl, Cmd и Alt, кроме пробела) и Backspace
переводят фокус в поле и срабатывают в нём — символ дописывается,
Backspace стирает последний. Так набор работает и после того, как мышь
увела фокус на пункт. Без поиска такого перехода нет.

Tab ходит по полю и пунктам в порядке разметки; ластики, как все ластики
пакета, вне порядка Tab.

## 8. Разметка и вид

Структура — как у `SelectSingle`: корень `bb-dashboard-ui`,
`ElementHeader`, `DropdownButton`, внутри панели — список пунктов
`ListElement` с пунктирными разделителями. Рамку, фон, скругление
и тень панели задаёт `DropdownButton`.

С поиском над списком — блок поля как `LocalFilterInput` russia
(классы — для ориентира, точный набор подбирает исполнитель):

- блок `px-2 py-2`, белый фон, снизу граница `gray-200`;
- поле на всю ширину блока: `px-3 py-2`, `text-sm`, рамка `gray-300`,
  `rounded-md`; в фокусе рамка и кольцо 1px `indigo-500`, без обводки
  браузера; ластик — справа внутри поля;
- строка «Ничего не найдено»: `px-3 py-2`, `text-sm`, `text-gray-500`,
  по центру;
- ширина панели — по самому широкому пункту, но не уже, чем нужно
  полю с подсказкой и ластиком; наименьшую ширину подбирает
  исполнитель.

Правила пакета: каждая утилита с префиксом `bb:`; содержимое кнопок
не ловит указатель и без курсора-руки; вид одинаковый в Playground
и в окружении приложения с `@tailwindcss/forms` — ресет корня
`bb-dashboard-ui` снимает с поля оформление приложения.

## 9. Языки

Новые ключи словарей `ru` и `en` в `src/i18n.js`:

| Текст | `ru` | `en` |
| --- | --- | --- |
| Надпись при нескольких выбранных | Выбрано: N | Selected: N |
| Подсказка и имя поля поиска | Поиск | Search |
| Нет совпадений | Ничего не найдено | Nothing found |

Проп `lang` (миксин `withLang`) действует на все тексты компонента,
в том числе на подпись для скринридера обоих ластиков — у кнопки
и в поле. Ластик `SelectSingle` по-прежнему берёт язык плагина.

## 11. Тесты

`tests/SelectMultiple.test.js`, по образцу `tests/SelectSingle.test.js`:
предупреждения Vue собираются через `warnHandler` и проверяются — вывод
тестов чистый.

Перенесённые из `SelectSingle` (те же проверки на `SelectMultiple`):
`null` в `items`; стрелки в открытом и закрытом списке; отсчёт от
выбранного; Escape и возврат фокуса, в том числе с body и без
прокрутки; фокус, ушедший на другой элемент, остаётся там; пункты
пропали при открытом списке; панель `popover="auto"`, клик вне,
прокрутка страницы и внутри, размер окна, место списка, второй список
закрывает первый; классы панели.

Свои:

- клик добавляет `id` в конец, повторный убирает; массив из пропа
  не меняется; `changed` после каждого клика;
- `id` вне пунктов сохраняются при переключении, не считаются

## 14. Как переходят компоненты russia

Справочно: перевод — отдельная задача (раздел 1). После подключения
пакета:

    <select-multiple header="Бренд" :items="brandItems" v-model="localSelectedBrands" @changed="updateFilter"/>
    <select-multiple header="Подразделение" :items="groupItems" v-model="localSelectedGroupsIds" @changed="updateFilter"/>
    <select-multiple header="Мероприятие" :items="eventItems" v-model="localSelectedEventsIds" with-search @changed="updateFilter"/>
    <select-multiple header="Пользователь" :items="userItems" v-model="localSelectedUsersIds" with-search @changed="updateFilter"/>

- `brandItems` — константа `[{ id: 'rc', name: 'Royal Canin' },
  { id: 'eukanuba', name: 'Eukanuba' }]` в russia;
- `groupItems`, `eventItems`, `userItems` — computed страницы:
  объекты моделей → `{ id: el.getObjectId(), name: el.getName() }`;
- именованные модели заменяются на `v-model`; `class` страницы
  (`h-18 border border-gray-200`, `max-w-5xl`) ложится на корень,
  как у `SelectSingle`;
- `updateFilter` страниц с этими фильтрами — Consumers, Events,
  Archive, Users, Activity, Sms — получает `preserveScroll: true`
  рядом с `preserveState: true` (4.2).

Что изменится для пользователей russia: список не закрывается после
клика; «Выбрано: 3» вместо «Выбрано брендов: 3»; подсказка «Поиск»
и «Ничего не найдено» вместо своих; запрос сбрасывается при закрытии
списка, а не при клике; появляются клавиатура и список в верхнем
слое; после смены фильтра страница остаётся на месте, а не уходит
наверх.

## 17. Принятые риски

- На iPad без клавиатуры открытие списка с поиском поднимает экранную
  клавиатуру: фокус встаёт в поле. Если Safari при этом прокрутит
  страницу, чтобы показать поле, прокрутка закроет список сразу после
  открытия. Не проверено; проверяет владелец при приёмке (раздел 16).
  Если список закрывается — отклонение от спеки, согласуется до
  исправления.
- Страница, которая перезапрашивает выдачу без `preserveScroll: true`,
  закрывает открытый список после ответа, если была прокручена (4.2).
- Подсказки Vimlike внутри открытого списка не видны — как у всех
  панелей пакета; выбирают стрелками и Enter.
- `changed` после каждого клика — по запросу на клик; Inertia отменяет
  предыдущий незавершённый визит.
- Общая надпись «Выбрано: N» без слова «брендов»: что выбрано, видно
  по заголовку фильтра.
- Фильтр поиска не приравнивает «ё» к «е» — как в russia.
