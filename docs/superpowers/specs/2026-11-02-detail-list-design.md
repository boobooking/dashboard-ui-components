# DetailList и DetailRow: строки карточки записи

Дата: 2026-11-02

## 1. Цель и рамки

Страницы просмотра записи в проектах показывают список строк: слева название,
справа значение, строки чередуются по цвету. Каждый проект держит свою копию
этой строки. Нужен компонент пакета, на который можно перевести все такие
карточки.

В рамках задачи:

- публичные компоненты `DetailList` и `DetailRow`;
- скрытие строк условием без сбоя чередования;
- тесты, Playground, README.

Вне рамок:

- перевод страниц проектов и подключение пакета к russia и belarus: это
  отдельные задачи в их репозиториях;
- блок выгрузки анкеты (`ConsumerCardCrmElement`) и карточки питомцев
  (`PetCard`): они остаются в проектах, блок стоит над списком, карточки
  лежат в значении строки;
- строка с красным фоном (`isError` в belarus): проп есть, вызовов нет;
- внешний вид карточки, шапка и крестик: это `PageCard`;
- подъём версии, тег и публикация: только по слову владельца.

## 2. Что показало исследование

Страницы с такими строками:

| Проект | Страница | Строк | Значения |
| --- | --- | --- | --- |
| russia | `Pages/Consumers/Show.vue` | 78 | текст, бейджи, список пород, карточки питомцев |
| belarus | `Pages/Consumers/Show.vue` | 24 | текст, бейдж, карточки питомцев |
| cashback | `Pages/DiscontoReceipt/Show.vue` | 11 | текст, суммы, `InfoPill`, галерея фото |
| cashback | `Pages/DiscontoPayment/Show.vue` | 8 | текст, суммы, `InfoPill` |

В certificates и payments таких страниц нет. Копии строки есть ещё
в overweight, cashback-vetkit-backend и health-days-backend; эти проекты пакет
не используют, их страницы не изучались.

Строка одинакова во всех изученных проектах (`ConsumerCardElement.vue`,
`CardElement.vue`):

```html
<div class="bg-white odd:bg-gray-50 px-4 py-5 sm:grid sm:grid-cols-3 sm:gap-4 sm:px-6">
    <dt class="text-sm leading-5 text-gray-500">…</dt>
    <dd class="mt-1 text-sm leading-5 font-medium text-gray-900 sm:mt-0 sm:col-span-2">…</dd>
</div>
```

- Название всегда задано текстом через проп `title`, слота нет. Один `title`
  вычисляемый: «Город» или «Страна».
- Строки прячет `v-if` на самой строке. `v-if` оставляет только комментарий,
  а `:nth-child` комментарии не считает, поэтому чередование не сбивается.
- В russia и belarus блок выгрузки — первый элемент `<dl>`, и первая строка
  чётная, белая. В cashback блока нет, первая строка нечётная, серая.
- В cashback список лежит в `PageCard` в обёртке
  `overflow-hidden sm:rounded-b-lg`. У `PageCard` своего `overflow-hidden`
  нет: крестик выходит за край карточки.
- В russia бейдж стоит с `class="ml-2"` и сдвинут относительно текстовых
  значений.

Правила пакета, которые здесь действуют:

- мобильных вариантов нет, порог ширины ставится, только если без него
  компонент не помещается в узкое окно десктопа (README, «Правила API пакета»);
- каждый экспортируемый компонент обязан иметь фикстуру в `tests/ssrFixtures.js`;
- ресет `.bb-dashboard-ui` действует на всё поддерево, включая слоты. `PageCard`
  и `DataTable`, у которых в слотах разметка приложения, такого класса на корне
  не несут.

## 3. Решения и их источники

| Решение | Источник |
| --- | --- |
| Компонент: строки с чередованием, две колонки, слева название в одном стиле, справа любое значение | владелец |
| Некоторые строки прячутся условием | владелец |
| Цвета и отступы — как в russia, образец на скриншоте владельца; порядок чередования — как в cashback | владелец |
| Первая строка серая, вторая белая, и так далее: владелец сначала выбрал белую первую строку, затем пересмотрел решение | владелец |
| Два компонента, `DetailList` и `DetailRow`, `title` пропом, значение в слоте, скрытие через `v-if` на строке | автор, показано владельцу |
| Внешний вид, шапка и крестик — `PageCard`, блок выгрузки — страница | автор, показано владельцу |
| Всегда две колонки, 1/3 и 2/3, складывания на узком окне нет | автор, показано владельцу; правило пакета |
| Разметка `<dl>`, `<dt>`, `<dd>` | автор, показано владельцу |
| Длинное значение без пробелов переносится внутри колонки | автор, показано владельцу |
| Список без видимых строк остаётся пустым блоком без высоты | автор, показано владельцу |
| Перевод страниц — отдельные задачи | автор, показано владельцу |
| Нижние углы скругляет сам `DetailList` | автор |
| На корне нет `bb-dashboard-ui`, отступы браузера снимают утилиты | автор |

## 4. API

### 4.1. Пример

Страница просмотра записи:

```vue
<page-card :fallback-url="route('consumers')">
    <div class="px-6 py-5 border-b border-gray-200">
        <h3 class="pr-(--bb-closer-space) text-lg font-medium">{{ eventName }}</h3>
    </div>
    <crm-card-element v-model:consumer="consumerObject" />
    <detail-list>
        <detail-row title="Регистрация">{{ registeredAt }}</detail-row>
        <detail-row v-if="phone !== null" title="Телефон">{{ phone }}</detail-row>
        <detail-row v-if="code !== null" title="Код">
            {{ code }} <info-pill class="ml-2" text="подтверждён" color="green" />
        </detail-row>
        <detail-row title="Согласие получать маркетинговые материалы">
            <info-pill text="согласен" color="green" />
        </detail-row>
    </detail-list>
</page-card>
```

### 4.2. DetailList

Пропсов и событий нет. Единственный слот по умолчанию — строки `DetailRow`.

В слоте лежат только строки: в итоговом DOM они — прямые дочерние элементы
списка. Чередование считает соседние элементы, поэтому обёртка вокруг строки
или другой элемент рядом с ней его собьёт. `v-if`, `v-for`, `<template v-if>`
и `<template v-for>` на строках чередованию не мешают, а `v-show` мешает:
строка остаётся в DOM. Блок выгрузки стоит над списком, а не внутри него.

### 4.3. DetailRow

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `title` | `String`, обязателен | — | Название строки |

Слот по умолчанию — значение: текст, пилюля, ссылка, список, любая разметка
страницы. Событий нет.

Без `title` Vue отмечает предупреждением о пропе в режиме разработки,
а компонент не падает: название пустое, значение на месте.

## 5. Вид

Значения классов — из строки проектов, без порогов ширины:

| Часть | Вид |
| --- | --- |
| Строка | сетка из трёх колонок с зазором 16 px, поля 24 px по бокам и 20 px сверху и снизу; нечётные строки `gray-50`, чётные белые |
| Название | первая колонка, `text-sm`, `leading-5`, `gray-500` |
| Значение | вторая и третья колонки, `text-sm`, `leading-5`, `font-medium`, `gray-900` |
| Список | нижние углы скруглены как у `PageCard` (`rounded-b-lg`), содержимое по ним обрезается |

- Чередование считается внутри списка, первая видимая строка серая, в том числе
  под блоком страницы над списком. Скрытая строка в счёт не входит.
- Название и значение начинаются от верха строки.
- Длинное значение без пробелов переносится внутри своей колонки и не раздвигает
  карточку. Название тоже переносится: в russia названия бывают длинные.
- Высота строки растёт по содержимому: строка с пилюлей выше строки с текстом,
  как в проектах. Отступ `ml-2` у пилюли, стоящей одной в значении, при переводе
  убирается, и она встаёт вровень с текстом соседних строк.
- Отступы браузера и preflight приложения на вид не влияют: у `<dl>`, `<dt>`,
  `<dd>` утилитами заданы нулевые внешние и внутренние отступы, у названия
  обычное начертание. Семейство шрифта наследуется от приложения, как во всём
  пакете.
- Список внутри `.prose` не поддерживается: в russia, belarus и cashback класса
  `prose` на страницах нет, а правила `@tailwindcss/typography` идут в CSS
  приложения позже правил пакета.

Ссылки в значении оформляет страница: пакет не меняет разметку слота.

## 6. Устройство

- `src/components/DetailList.vue` — `<dl>` со слотом.
- `src/components/DetailRow.vue` — `<div>` с `<dt>` и `<dd>`.
- `src/index.js` — экспорт обоих. Плагин `dashboardUi` не меняется: компоненты
  он не регистрирует.
- Классы литералами с префиксом `bb:`, чередование — вариант `bb:odd:` на строке.
- `bb-dashboard-ui` на корне нет: в значении лежит разметка приложения, ресет
  пакета снял бы её отступы. Как у `PageCard` и `DataTable`.

## 7. README, Playground, тесты

**README.**

- Новые разделы `DetailList` и `DetailRow` рядом с `PageCard`: пример раздела 4.1,
  таблица пропа, правило о прямых дочерних элементах, вид.
- Абзац о странице просмотра в разделе `PageCard`: строки — `DetailList` вместо
  обёртки `overflow-hidden rounded-b-lg`.
- Число и перечень компонентов: «тридцать три» в разделе «Компоненты»
  и в разделе «Playground».

**Playground.** Раздел `DetailList`: `PageCard` с шапкой и строками разных значений
(текст, текст с пилюлей, одна пилюля, список, длинное название, длинное значение
без пробелов) и кнопка, которая прячет и показывает одну строку.

**Тесты (Vitest).**

- `DetailRow`: разметка `div` > `dt` + `dd`, `title` в `dt`, слот в `dd`, классы
  двух колонок; без порогов ширины; без `title` — предупреждение и без ошибок.
- `DetailList`: разметка `dl`, строки в слоте; пустой слот не падает.
- Сторож: классы `bb:m-0`, `bb:p-0` у `dl`, `dt`, `dd`, `bb:font-normal` у `dt`.
- На корнях нет `bb-dashboard-ui`.
- `tests/exports.test.js`: тридцать три компонента.
- Фикстуры `tests/ssrFixtures.js`: `DetailList` со строкой и `DetailRow`.

**Тесты (Playwright, Chromium и WebKit).** Обе страницы Playground:

- фон первой строки `gray-50`, второй белый, третьей `gray-50`;
- спрятанная строка: чередование считается заново по видимым строкам;
- все строки спрятаны: высота списка 0;
- две колонки при ширине окна 360 px: `dt` и `dd` на одной линии;
- длинное значение без пробелов: у карточки нет горизонтальной прокрутки, текст
  значения в границах своей колонки, проверка по прямоугольнику текста, а не `dd`;
- нижний край при нечётном числе строк: угол последней серой строки обрезан
  скруглением, проверка по изображению угла, падает при снятии обрезки;
- нулевые отступы `dl`, `dt`, `dd` и обычное начертание `dt` в окружении приложения
  (`host.html`).

**Приёмка.** В Chrome — исполнитель, в Safari — владелец, в Playground.

## 8. Выпуск

Работа идёт на ветке `feat/detail-list` от локального `main`, где лежит
неопубликованный коммит иконок действий. Версия, тег и публикация — только по
слову владельца.
