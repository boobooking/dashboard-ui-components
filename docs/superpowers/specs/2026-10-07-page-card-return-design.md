# PageCard: возврат туда, откуда открыли

Дата: 2026-10-07

## 1. Цель и рамки

`PageCard` закрывается крестиком «назад по истории» (`history.back()`, крестик
виден при `history.length > 1`). Для карточки из нескольких страниц — табов,
фильтров, пагинации — история не годится: «назад» уводит на предыдущий таб,
а не туда, откуда карточку открыли. В certificates это обошли иначе: фильтры
страницы-источника (`/groups?status=…`) ехали в адресе карточки и обратно,
и это сломало карточку группы — фильтры двух страниц делили один query string
(раздел 2).

Цель: универсальный `PageCard`, который сам знает, откуда его открыли, и по
крестику или «Отмене» возвращает ровно туда — на адрес страницы-источника со
всеми её фильтрами и номером страницы. Без адреса страницы, без хранилищ
браузера, без истории браузера. Страницы внутри карточки (табы) ничего об
этом не знают.

«Как было» — это адрес страницы-источника: путь, фильтры, номер страницы.
Позиция прокрутки, несохранённый ввод и раскрытые элементы источника — его
собственное состояние, `PageCard` их не возвращает.

В рамках задачи (выпуск пакета `0.13.0`):

- опция `currentUrl` плагина `dashboardUi`;
- внутренний модуль окон `src/windows.js` (не экспортируется);
- `PageCard`: адрес возврата из окна, пропы `width`, `fallback-url`,
  `window-key`, `close()` для «Отмены», работа постоянным макетом страниц,
  `history` уходит;
- модульные и интеграционные тесты, playground, README, выпуск `0.13.0`.

Вне рамок:

- перевод certificates — своя спека в репозитории certificates
  (`docs/superpowers/specs/2026-10-07-page-card-return-design.md`);
- перевод payments (7 страниц) и cashback (6 страниц) — свои задачи
  (раздел 9);
- новые экспортируемые компоненты: их не появляется.

## 2. Что показало исследование

**Сломанная карточка группы в certificates.** Карточка возила фильтры
страницы `/groups` в своём адресе (`filterQuery`), чтобы крестик вернул на
отфильтрованный список. У `/groups` есть фильтр `status` (статус группы),
у таба ордеров карточки — свой `status` (статус ордера). Воспроизведено
в браузере:

- выбор статуса ордера «Отправлен» → адрес `?status=sent`, сервер принимает
  его и за фильтр `/groups`, ссылки всех табов получают `?status=sent`;
- ластик фильтра → запрос уходит снова с `?status=sent`: компонент пуст,
  адрес и выдача прежние;
- крестик → `GET /groups?status=sent` → 302 обратно на карточку: `sent` —
  не статус группы;
- с `/groups?status=sending` карточка не открывается вовсе: `sending` — не
  статус ордера, 302 обратно.

Вывод владельца: страницы — разные компоненты, у них не должно быть ничего
общего; совпадение имён фильтров не должно ни на что влиять, а адрес
возврата не должен лежать в адресе страницы.

**Использование `PageCard`.** 14 мест: payments — 7, cashback — 6,
certificates — 1 (плюс playground). Везде приложение передаёт на корень только
`class`, других атрибутов нет.

**Inertia (проверено в `@inertiajs/core` и `@inertiajs/vue3` 3.6.1).**

- Показ страницы: `history.pushState` или `replaceState` → `swapComponent`
  присваивает `component.value`, затем `page.value`, затем `key.value` →
  Vue отрисовывает новую страницу. Отрисовка асинхронная, поэтому все три
  присваивания происходят до создания компонентов новой страницы.
- Событие `navigate` приходит после подмены компонента, но только для
  перехода с новой записью истории: в коде `if (!replace)`. Переход
  с заменой записи (`replace: true`) и любой переход на текущий адрес
  (Inertia сама делает его заменой) события не шлют. Без `preserveState`
  такой переход ещё и пересоздаёт страницу (`key.value = Date.now()`).
- «Назад»/«Вперёд» браузера и первая загрузка тоже проходят через
  присваивание `page.value`. Начальную страницу Inertia присваивает в
  `setup()` своего компонента `App`, то есть после `.use(...)` плагинов:
  при установке плагина `usePage().url` ещё `undefined`.
- `usePage()` работает вне компонентов: это реактивный объект уровня
  модуля, `usePage().url` — вычисляемое значение от `page.value.url`.
  Неуспешный или отменённый переход `page.value` не меняет; ответ с
  ошибками валидации меняет его на тот же адрес.
- Постоянный макет: `layout` страницы — компонент, кортеж
  `[Компонент, пропы]` или функция одного аргумента (пропы страницы),
  возвращающая кортеж. Один и тот же компонент макета на соседних страницах
  не пересоздаётся: Vue обновляет его пропы, меняется только страница
  в слоте.
- Макету Inertia передаёт все пропы страницы и выставляет компоненту макета
  `inheritAttrs = !!inheritAttrs`. Без явного `inheritAttrs: true`
  наследование атрибутов выключается у самого объекта компонента — для всех
  его использований.
- HTTP-клиент Inertia подменяется через `http.setClient(client)`: этим
  пользуются интеграционные тесты (раздел 6).

**Ziggy.** `route()` по умолчанию возвращает абсолютный адрес
(`https://certificates.test/groups`), а `usePage().url` — путь
(`/groups?status=sending`). Адреса надо приводить к одному виду (4.2).

## 3. Решения и их источники

| Решение | Источник |
| --- | --- |
| Адрес возврата не кладётся в адрес страницы | владелец: «добавлять их в урл это ужасное решение» |
| Никакой зависимости от истории браузера | владелец |
| Никакого `sessionStorage` и других хранилищ | владелец: «очень ненадёжный источник» |
| Возврат — только на адрес, переданный при открытии | владелец |
| Один `PageCard` на всю карточку, табы о возврате не знают | владелец |
| Крестик и «Отмена» — одно действие: закрыть активное окно | владелец |
| Каждая форма — своё окно со своим видом, без шапки внешней карточки | владелец |
| Возврат «как было» — для всех возвратов, в том числе после успешного действия | владелец |
| Адрес берёт сам `PageCard`, без отдельной ссылки-компонента | владелец |
| Никаких миксинов: разработчик знает только `PageCard` | владелец: «надо постараться спрятать эту сложность» |
| `fallback-url` остаётся | владелец |
| Отдельного компонента-макета нет, `PageCard` годится в макет сам | владелец |
| Пакет не зависит от Inertia | владелец; связь с роутером — опции плагина, как `navigate` |
| Плагин узнаёт адрес из реактивного `currentUrl`, а не из события | ревью: событие `navigate` пропускает `replace` (раздел 2) |
| Окно — сущность с ключом и родителем, компонент — его временное представление | ревью: пересоздание компонента не должно открывать окно |
| Карточка из нескольких страниц задаёт `window-key` | ревью: разные сущности в одном макете — разные окна |
| Алгоритм окон — во внутреннем модуле `src/windows.js` | ревью: чистый модуль проще проверить, чем хуки компонента |
| Ключ по умолчанию следует за путём страницы | ревью: роутер переиспользует экземпляр страницы для другой сущности |
| Смена ключа — только вместе с показом страницы, иначе предупреждение | ревью: окно без навигации некуда закрывать |
| `currentUrl()` до готовности роутера может вернуть `undefined`/`null` | ревью: Inertia задаёт страницу после установки плагинов |

## 4. Адреса и окна

### 4.1. Опция `currentUrl`

```js
import { router, usePage } from '@inertiajs/vue3'

createApp(App).use(dashboardUi, {
    navigate: (href) => router.visit(href),
    currentUrl: () => usePage().url,
})
```

`currentUrl()` — адрес страницы, которая сейчас на экране. Договор:

- функция читает реактивное состояние роутера, и её значение меняется при
  каждом показе страницы с новым адресом — в том числе при замене записи
  истории, при «Назад»/«Вперёд» и при первой загрузке;
- новое значение появляется до создания компонентов новой страницы;
- неуспешный или отменённый переход значения не меняет;
- пока роутер не готов, функция может вернуть `undefined` или `null`.
  Такое значение плагин не приводит к адресу и показом не считает; первое
  настоящее значение — показ без прежней страницы. Это не то же самое,
  что опция `currentUrl: undefined`: сама опция обязана быть функцией.

Inertia 3.6.1 выполняет договор (раздел 2). Рецепт в README — только для
Inertia: все проекты на ней, а опубликованный рецепт для другого роутера
требует своего теста холодного открытия. Для другого роутера приложение
пишет функцию по договору само; например, у Vue Router до первой
навигации `currentRoute` — `START_LOCATION` с `fullPath === '/'`, и такое
значение функция обязана отдавать как `null`.

Плагин следит за значением синхронно (`watch` с `flush: 'sync'`,
`immediate: true`) внутри своей области эффектов и останавливает слежение
при размонтировании приложения (`app.onUnmount`). Слежение ставится только
в браузере (`typeof window !== 'undefined'`): на сервере окон нет.

Проверка — как у `navigate`: ключ передан — значение обязано быть функцией,
иначе ошибка в `app.use`, включая `null` и `undefined`. Без `currentUrl`
окна не ведутся, у `PageCard` нет адреса возврата, и он закрывается только
на `fallback-url` (5.3).

Состояние плагина — у каждого приложения своё: создаётся в `install()`
и отдаётся компонентам через тот же `provide`, что и настройки. Переменных
уровня модуля нет: при серверном рендеринге запросы разных пользователей
не делят одно состояние.

### 4.2. Адрес

Адрес — путь и query string без origin и hash: `/groups?status=sending`.
К этому виду приводится всё, что сравнивается: значение `currentUrl()`,
`fallback-url` (Ziggy даёт абсолютный адрес) и адрес возврата. Приведение —
разбор `new URL(значение, location.origin)` и `pathname + search`.
Сравнение — строковое равенство приведённых адресов.

`fallback-url` — пустая строка или `null`: цели нет.

### 4.3. Модель

Три понятия разделены:

- **Окно** — сущность модуля окон: `id`, ключ, родитель (окно, из которого
  его открыли, или `null`), адрес возврата (неизменяемый снимок адреса
  источника в момент открытия, может быть `null`) и `fallback-url`
  карточки. Цель окна — адрес возврата, а если его нет, `fallback-url`.
- **Карточка** — экземпляр `PageCard`, временное представление окна. Её
  пересоздание само по себе окна не открывает и не закрывает.
- **Показ страницы** — смена значения `currentUrl()`. При каждой смене
  модуль запоминает переход: адрес прежней страницы и окно, карточка
  которого была на экране (или `null`).

Открытые окна образуют цепочку от корня к окну на экране: у каждого,
кроме корня, родитель — предыдущее окно цепочки.

**Ключ окна** — проп `window-key`, а без него путь страницы на экране
(путь из `currentUrl()`, без query). Ключ по умолчанию следует за путём,
пока карточка на экране: если роутер переиспользовал экземпляр страницы
для другой сущности (`/users/1/edit` → `/users/2/edit` с `preserveState`),
у карточки новый ключ и новое окно. Отдельная страница-карточка ключ не задаёт. Карточка из нескольких
страниц (табы) задаёт общий для них ключ сущности, например
`group:<uuid>`: путь у табов разный, а окно одно.

**Переход** — запись модуля при каждом показе страницы: номер, адрес
прежней страницы, окно прежней страницы и назначения, сделанные на этом
переходе.

### 4.4. Правила

Карточка получает окно («назначение») в двух случаях:

- **монтирование** — новый экземпляр карточки;
- **смена ключа** у карточки на экране — явного `window-key` или пути при
  ключе по умолчанию. Смена ключа допустима только вместе с новым
  показом страницы. Карточка помнит номер последнего обработанного ею
  перехода и проверяет пару «номер перехода + ключ» после каждой
  отрисовки:
  - номер новый, ключ прежний — переход отмечается обработанным, окно
    не меняется (смена таба);
  - номер новый, ключ другой — `release`, затем `assign` с новым ключом,
    переход отмечается обработанным;
  - номер прежний, ключ другой (ключ сменили без смены адреса, в том числе
    после уже обработанного перехода между табами) — проверка срабатывает
    до `release`: карточка остаётся в своём окне со своим ключом, а пакет
    пишет предупреждение в консоль (`console.warn`) с обоими ключами.
    Окно без навигации пакет не открывает: возвращаться из него было бы
    некуда — адрес тот же.

На входе назначения — ключ карточки, её `fallback-url`, адрес на экране
и последний переход:

1. **Повтор.** Если на этом переходе для того же ключа окно уже
   назначалось и это окно ещё открыто, карточка получает его. Так
   пересоздание страницы на том же адресе без нового показа (переход на
   текущий адрес, `replace`) не плодит окон. Закрытое окно правило 1
   не возвращает: назначение идёт дальше по правилам 2–5.
2. **Возврат из окна.** Если окно прежней страницы открыто и его цель равна
   адресу на экране — пришли туда, куда это окно возвращает: оно и всё над
   ним закрываются. Дальше правила 3–5 применяются так, будто прежней
   страницей было его родительское окно, а адреса прежней страницы нет:
   на страницу закрытого окна вести нельзя.
3. **Окно в цепочке.** Если окно с ключом карточки — окно прежней страницы
   или его предок, карточка получает его; окна над ним закрываются. Так
   работают возврат на таб кнопкой «Назад» браузера и прыжок по истории
   через несколько записей.
4. **Вложенное окно.** Иначе, если окно прежней страницы есть, окна над
   ним закрываются, и открывается новое окно: родитель — окно прежней
   страницы, адрес возврата — адрес прежней страницы.
5. **Новая цепочка.** Иначе (прежняя страница без карточки или первая
   загрузка) все окна закрываются, открывается новое корневое окно
   с адресом возврата прежней страницы (`null` при первой загрузке).

Окно, из которого ушли не через его цель (ссылкой в другой раздел),
закрывается правилом 5 при следующем открытии карточки со страницы без
карточки или правилами 3–4 внутри цепочки. Поиск по ключу идёт только
по цепочке окна прежней страницы, поэтому брошенные окна ни в какой
поиск не попадают.

`close()` состояния не меняет: окно закрывается правилом 2 или 5, когда
страница-цель действительно показана. Неуспешный или отменённый переход
оставляет окно открытым, и `close()` можно повторить.

Пример — карточка группы с табами (постоянный макет, `window-key =
group:A`) и формой ключей (отдельная страница со своим `PageCard`):

| Шаг | Правило | Цепочка после шага |
| --- | --- | --- |
| `/groups?status=sending` (фильтр поставлен с `replace`), «Посмотреть» → таб ордеров | 5 | группа (→ `/groups?status=sending`) |
| смена табов, фильтров (в том числе `replace`), страниц таблицы | — | без изменений: макет не пересоздаётся |
| таб сертификатов `?vendor=X` → «Добавить ключи» | 4 | группа; ключи (→ таб `?vendor=X`) |
| крестик формы / «Назад» браузера / успешная загрузка → таб `?vendor=X` | 2, 3 | группа |
| прыжок по истории с формы сразу на таб ордеров | 3 | группа |
| крестик на табе → `/groups?status=sending` | — | без карточки на экране; окно закроет правило 5 |
| F5 на форме: форма без адреса, крестик → `fallback-url` формы (таб без фильтров) | 5, затем 2 и 5 | группа без адреса → её крестик на её `fallback-url` |
| в том же макете группа A → группа B (`window-key` сменился вместе с адресом) | 4 | группа A; группа B (→ таб группы A) |
| `/users?page=2` → `/users/1/edit` → `/users/2/edit` с `preserveState` (карточка та же, путь сменился) | 5, затем 4 | редактор 1; редактор 2 (→ `/users/1/edit`) |
| холодное открытие карточки: первая загрузка сразу на `/users/1/edit` | 5 | редактор 1 без адреса → крестик на `fallback-url` или его нет |

### 4.5. Модуль окон

`src/windows.js` — чистый модуль без Vue и DOM: состояние (окна, переход,
назначения перехода) и функции `createWindows()`, `pageShown(url)`,
`assign(card, key, fallbackUrl)`, `release(card)`, `targetOf(card)`,
`setFallback(card, fallbackUrl)`. Плагин создаёт состояние на приложение
и зовёт `pageShown` из слежения за `currentUrl`; `PageCard` зовёт
`assign`, `release`, `targetOf` и `setFallback`. Наружу модуль не
экспортируется. Имена функций уточняет план.

## 5. `PageCard`

### 5.1. Пропы

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `width` | `String` | `"xl"` | `"xl"`, `"4xl"` или `"7xl"` |
| `fallback-url` | `String` | `null` | куда закрываться, если адреса возврата нет |
| `window-key` | `String` | путь страницы на экране | ключ окна; задаёт карточка из нескольких страниц |
| `lang` | `String` | язык плагина | `"ru"` или `"en"` |

Недопустимый `width` — предупреждение валидатора Vue в dev-сборке и вид
`"xl"`. Событий нет.

### 5.2. Разметка, ширина, атрибуты

Корень — карточка, как сейчас (`box-border relative my-6 mx-auto bg-white
shadow-xl sm:rounded-lg`), ширина и порог крестика — по `width`:

| `width` | Ширина от `sm` | Крестик снаружи карточки | `--bb-closer-space` |
| --- | --- | --- | --- |
| `xl` | `max-w-xl` (36rem) | от `md` | `3.5rem` ниже `md`, `0` от `md` |
| `4xl` | `max-w-4xl` (56rem) | от `lg` | `3.5rem` ниже `lg`, `0` от `lg` |
| `7xl` | `max-w-7xl` (80rem) | от `2xl` | `3.5rem` ниже `2xl`, `0` от `2xl` |

Порог — наименьшая стандартная точка, где область шириной `W + 2 × 3rem`
вмещает карточку и крестик с зазором (расчёт §4 спеки `PageCard`
2026-09-29): `42rem` → `md`, `62rem` → `lg`, `86rem` → `2xl`. Без крестика
переменная равна `0` на любой ширине. Классы трёх вариантов записаны в
исходнике целиком, чтобы сборка Tailwind пакета их нашла.

`inheritAttrs: false`. На корень переносятся `class`, `style`, `data-*`
и `aria-*` приложения; классы приложения по-прежнему сильнее классов
пакета. Остальные атрибуты не переносятся: когда `PageCard` — макет,
Inertia передаёт ему пропы страницы атрибутами. Пропы страницы — имена
вида `group`, `orders`, `id`; с `data-` и `aria-` они не начинаются, а
`id` в список не входит именно потому, что так часто называют проп
страницы.

### 5.3. Крестик и `close()`

- Цель карточки — цель её окна (4.3); без окна (нет плагина или
  `currentUrl`) — `fallback-url`. Крестик показан, если цель есть. Без цели
  крестика нет, и `--bb-closer-space` равна `0`.
- Клик, Enter и пробел на крестике — `close()`.
- `close()` — публичный метод (`this.$refs.card.close()`) и он же проп слота
  по умолчанию: `<page-card v-slot="{ close }">` … `@click="close"`. Им
  «Отмена» страницы и код после успешного действия закрывают окно.
- `close()` переходит на цель через `navigate` плагина; без `navigate` —
  `window.location.assign(цель)`. Без цели `close()` ничего не делает.
  Результата `close()` не возвращает: окно закрывается, когда цель показана
  (4.4).
- Доступность крестика — как сейчас: `tabindex="0"`, кольцо при фокусе
  с клавиатуры, `aria-label` из словаря (`back`: «Назад» / «Back»).

`history.length` и `history.back()` компонент больше не использует.

### 5.4. Жизненный цикл

- `mounted()` — `assign` с ключом и `fallback-url`. Назначение синхронное:
  переход записан плагином до создания компонентов страницы (4.1), ждать
  нечего.
- Ключ карточки — вычисляемое значение: `window-key`, а без него путь из
  `currentUrl()`. Номер последнего перехода плагин держит в реактивном
  `ref`. Карточка следит за парой «номер перехода + ключ» с
  `flush: 'post'`, то есть после отрисовки, и применяет правило смены
  ключа из 4.4. Карточка, которую уносит переход, к этому моменту уже
  размонтирована, её слежение остановлено, и окно новой страницы она
  себе не возьмёт.
- Смена `fallback-url` — `setFallback`.
- `beforeUnmount()` — `release`: окно остаётся открытым, его может
  получить карточка следующей страницы (правила 2–3).

### 5.5. Постоянный макет

Карточку из нескольких страниц Inertia (табы) объявляют постоянным макетом
этих страниц и дают ей ключ сущности:

```js
export default {
    layout: (props) => [PageCard, {
        width: '7xl',
        windowKey: `group:${props.group.data.uuid}`,
        fallbackUrl: route('groups'),
        class: 'px-4 py-4 sm:px-6 sm:py-6',
    }],
    // …
}
```

Пока соседние страницы объявляют тот же макет, `PageCard` не пересоздаётся;
окно одно, пока не сменился `window-key`. Отдельная страница со своим видом
(форма) держит `<page-card>` в своём шаблоне и становится своим окном.
Рецепт проверен на `@inertiajs/vue3` 3.6.1; пакет от Inertia не зависит.

### 5.6. SSR

На сервере окон нет: слежение за `currentUrl` не ставится, `mounted()`
не выполняется. Сервер рисует крестик, только если задан `fallback-url`;
гидратация совпадает, потому что до `mounted()` клиент рисует то же. Если
адрес возврата пришёл при монтировании, крестик появляется после
гидратации.

### 5.7. Устойчивость

- Без плагина или без `currentUrl`: только `fallback-url`.
- Плагин без `navigate`: `close()` переходит полной загрузкой страницы.
- `fallback-url` — пустая строка: цели нет, как у `null`.
- На одной странице — одна карточка; две карточки на одной странице
  не поддерживаются.

## 6. Тесты

**`tests/windows.test.js`** — модуль окон без Vue, таблицами переходов:
последовательность `pageShown`/`assign`/`release` → ожидаемая цепочка и
цели. Случаи — все правила 4.4 и все строки примера, а также:

- повторное назначение на том же переходе даёт то же окно, окна не
  копятся (три пересоздания — одно окно);
- правило 1 не возвращает закрытое окно;
- смена ключа без нового перехода (A → B → A на одном адресе): карточка
  остаётся в окне A, окна не меняются, предупреждение одно — на попытку
  установить B; возврат пропа к принятому ключу A контракт не нарушает

**`tests/inertia.test.js`** — интеграция с настоящими `@inertiajs/vue3`

1. фильтр списка через `replace` → открытие карточки → крестик: адрес

## 11. Принятые риски

- Память плагина не переживает F5 и открытие в новой вкладке: окно
  закрывается на `fallback-url`, фильтры страницы-источника теряются.
  Это следствие запрета на хранилища и адрес страницы.
- Роутер, чей `currentUrl` меняется после создания компонентов новой
  страницы, нарушает договор 4.1: карточка получит окно прежней страницы.
  Inertia 3.6.1 договор выполняет; другие роутеры проверяются при
  подключении.
- Адреса сравниваются строкой: если после формы сервер редиректит на
  равнозначный адрес с другим порядком параметров или с лишним `page=1`,
  правило 2 не сработает. Когда у формы есть родительское окно с ключом
  страницы прихода, его найдёт правило 3, и возврат будет верным. Риск
  остаётся, только когда родителя нет — форму открыли прямой ссылкой или
  после F5: карточка страницы прихода откроет вложенное окно с возвратом
  на форму. Возвраты пакета (`close()`, «Назад» браузера) приходят ровно
  на запомненный адрес; в certificates формы закрываются сами, без
  серверного редиректа.
- Смену ключа без смены адреса пакет не поддерживает: карточка остаётся
  в прежнем окне и пишет предупреждение (4.4).
- Если вернуться в карточку кнопкой «Вперёд» или «Назад» браузера после
  ухода из неё не через крестик, адрес возврата — страница, с которой
  пришли в этот раз.
- Две карточки на одной странице не поддерживаются.
