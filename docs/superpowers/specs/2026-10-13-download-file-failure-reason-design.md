# Причина отказа `downloadFile` в полях ошибки

Дата: 2026-10-13

## 1. Цель и рамки

`downloadFile(url)` отказывает простым `Error`, и страница не может отличить
истёкшую сессию от ошибки сервера. Ссылка вела браузер за перенаправлением
сервера на страницу входа, а страница с `downloadFile` при истёкшей сессии
показывает «Попробуйте ещё раз», и повтор снова падает, пока пользователь не
перейдёт куда-нибудь по дашборду.

Цель — сообщать причину отказа в полях ошибки, чтобы страница могла отправить
пользователя туда, куда направил сервер.

В рамках задачи (выпуск `0.16.3`):

- поля `redirectUrl` и `status` у ошибок `downloadFile`;
- тесты: нынешние с подменённым `fetch` и новые с настоящим локальным
  HTTP-сервером;
- README, раздел `downloadFile`; Playground;
- версия `0.16.3` последним коммитом.

Вне рамок:

- перевод cashback на `0.16.3` — своя спека в cashback после выпуска;
- certificates и payments — свои задачи в своих репозиториях;
- переход на страницу входа внутри пакета: пакет не импортирует Inertia,
  переход делает страница (раздел 3);
- проверка в браузере: настоящий ответ Laravel проверяется на приёмке
  cashback (раздел 9).

## 2. Что показало исследование

**Нынешний код** (`src/download.js`, `0.16.2`):

```js
if (response.redirected) {
    throw new Error(`downloadFile: сервер перенаправил запрос ${url}`)
}

if (!response.ok) {
    throw new Error(`downloadFile: ответ ${response.status} на ${url}`)
}
```

Сетевая ошибка приходит ошибкой самого `fetch` (`TypeError`) без обёртки.
Причина есть только в тексте сообщения, а разбирать текст — хрупко.

**Истёкшая сессия в Laravel.** Middleware `auth` на запрос без
`Accept: application/json` отвечает `302` на страницу входа. `fetch` идёт за
перенаправлением сам: `response.redirected` — `true`, `response.url` — адрес
страницы входа. Промежуточный `Location` `fetch` не отдаёт: с
`redirect: 'manual'` ответ непрозрачный (`opaqueredirect`).

**Страницы на `0.16`.** certificates («Ордеры», «скачать xlsx») на любой
отказ показывает «Не удалось скачать отчёт» / «Попробуйте ещё раз»; спека
certificates принимает это как риск. cashback переходит на `0.16` и хочет
при истёкшей сессии вести на вход.

**Playground** показывает отказ текстом сообщения:
`ошибка: ${error.message}`.

## 3. Решения и их источники

| Решение | Источник |
| --- | --- |
| Причина отказа — в полях ошибки, решает страница; `downloadFile` сам не переходит | владелец, выбор из двух подходов |
| Поля `redirectUrl` и `status` у обычного `Error`, без своего класса и новых экспортов | дизайн, одобрен |
| Тексты сообщений не меняются | дизайн, одобрен |
| Тест с настоящим локальным HTTP-сервером рядом с тестами на подменённом `fetch` | дизайн, одобрен |
| Версия `0.16.3`: поля только добавляются, `^0.16.x` подтянет выпуск без правок проектов | владелец |

**Почему не переход внутри `downloadFile`.** Пакет не импортирует Inertia,
и переход был бы полной загрузкой страницы мимо роутера приложения. Promise
тогда пришлось бы либо отклонять — перед уходом мелькнуло бы уведомление об
ошибке, — либо не завершать вовсе, и пилюля осталась бы с часами, если
перенаправление не уводит со страницы.

## 4. `downloadFile` — поля ошибки

| Отказ | Ошибка | `redirectUrl` | `status` |
| --- | --- | --- | --- |
| Сервер перенаправил (`response.redirected`) | `Error`, текст как сейчас | `response.url` — адрес, куда в итоге привёл сервер | `null` |
| Ответ не `2xx` | `Error`, текст как сейчас | `null` | `response.status` |
| Сетевая ошибка | ошибка `fetch`, тот же объект | поля нет | поля нет |

```js
if (response.redirected) {
    throw Object.assign(new Error(`downloadFile: сервер перенаправил запрос ${url}`), { redirectUrl: response.url, status: null })
}

if (!response.ok) {
    throw Object.assign(new Error(`downloadFile: ответ ${response.status} на ${url}`), { redirectUrl: null, status: response.status })
}
```

Комментарий над проверкой перенаправления дополняется: `redirectUrl` — чтобы
страница могла отправить пользователя туда же, куда отправила бы ссылка.
Остальное в функции не меняется: запрос, имя файла, скачивание,
освобождение blob-адреса.

Проверка на странице — по полю: `error.redirectUrl` (строка или `null`),
`error.status` (число или `null`). У сетевой ошибки полей нет, и обе проверки
дают «нет».

## 5. Тесты

**`tests/download.test.js`** — в нынешнем стиле, с подменённым `fetch`.
Хелпер `response()` получает поле `url` (по умолчанию `''`). Блок «отказ»:

- перенаправление: `redirectUrl` равен `url` ответа, `status` — `null`,
  `message` — полностью прежний текст, ссылка не кликнута;
- перенаправление, которое закончилось ответом `404`: отказ как при
  перенаправлении — `redirectUrl` равен `url` ответа, `status` — `null`;
  тест держит порядок проверок;
- 404 и 500: `status` — код, `redirectUrl` — `null`, `message` — полностью
  прежний текст, файла нет;
- сетевая ошибка: отказ тем же объектом, у него нет собственных свойств
  `redirectUrl` и `status`.

**`tests/download.server.test.js`** (новый) — без комментария окружения, как
`colors.test.js`: окружение `node`. Настоящий `fetch` Node по стандарту Fetch
идёт за перенаправлением так же, как браузер, и сам заполняет `redirected`
и `url`; в подменённом `fetch` эти значения пишутся руками.

Сервер `node:http` на `127.0.0.1`, порт `0` (свободный), поднимается
в `beforeAll`, закрывается в `afterAll`:

| Путь | Ответ |
| --- | --- |
| `/export` | `302`, `Location: /login` |
| `/login` | `200`, `text/html`, разметка формы |
| остальное | `404` |

- ``downloadFile(`${origin}/export`)`` отказывает: `redirectUrl` —
  `${origin}/login`, `status` — `null`;
- ``downloadFile(`${origin}/missing`)`` отказывает: `status` — `404`,
  `redirectUrl` — `null`.

До DOM функция в этих случаях не доходит: отказ происходит до
`URL.createObjectURL` и `document`.

## 6. README, раздел `downloadFile`

Пункт об отказах заменяется:

> - Promise отклоняется:
>   - при перенаправлении — обычно на страницу входа после истёкшей сессии:
>     у ошибки `redirectUrl` — адрес, куда в итоге привёл сервер, `status` —
>     `null`;
>   - при ответе не `2xx`: `status` — код ответа, `redirectUrl` — `null`;
>   - при сетевой ошибке — ошибкой `fetch`, без этих полей.

После списка — абзац и пример:

> Ссылка при истёкшей сессии привела бы браузер на страницу входа. Чтобы
> страница вела себя так же, она сама переходит по `redirectUrl`: пакет
> не импортирует ни Inertia, ни роутер. В приложении на Inertia:
>
> ```js
> import { router } from '@inertiajs/vue3'
>
> exportOrders() {
>     this.exportFailure = "";
>     this.exportLoading = true;
>
>     downloadFile(this.exportUrl)
>         .catch((error) => {
>             if (error.redirectUrl) {
>                 router.visit(error.redirectUrl);
>                 return;
>             }
>
>             this.exportFailure = "Попробуйте ещё раз";
>         })
>         .finally(() => {
>             this.exportLoading = false;
>         });
> }
> ```

Первый пример раздела не меняется. Раздела «Обновление с 0.16» нет:
выпуск ничего не ломает.

статический Playground показать не может.

## 9. Выпуск

Ветка — текущая `main`. Порядок:

1. `feat:`-коммит: `src/download.js`, тесты, README, Playground;
2. `npm test` — все тесты зелёные, вывод без предупреждений;
   `npm run build`; сборка Playground (`vite.playground.config.js`) —
   сборка библиотеки его не проверяет;
3. итоговое ревью;
4. `chore:`-коммит с `0.16.3` в `package.json` и двух местах
   `package-lock.json` — последним;
5. пуш `main`, зелёный `Test` по полному SHA версионного коммита, тег
   `v0.16.3` на этот SHA, пуш одного тега; публикует workflow `Publish`.

Пуш и тег — по слову владельца.

Проверка в браузере — на приёмке cashback: выход из системы во второй
вкладке, «скачать xls» в первой ведёт на страницу входа. Расхождение
браузера с Node — выпуск `0.16.4`.

## 10. Принятые риски

- `redirectUrl` — адрес после всех перенаправлений, а не первый `Location`:
  `fetch` промежуточных не отдаёт. Для истёкшей сессии это и есть страница
  входа.
- Перенаправление на другой домен без CORS `fetch` обрывает сетевой ошибкой:
  полей не будет, страница покажет общий отказ. Дашборды входят на своём
  домене.
- Своего класса ошибки нет: отличать отказы `downloadFile` через
  `instanceof` нельзя, только по полям.
- В браузере поля проверяются после выпуска, на приёмке cashback.
